01 Kodun nerede çalışıyor?

Telefondan Claude Code kullanmanın tek bir yolu yok, üç tane var ve aralarındaki fark tek bir soruda toplanıyor: kod kimin makinesinde çalışıyor? Yanlış olanı seçersen ya laptopu açık bırakmak zorunda kalırsın ya da yerel MCP server'ların yokluğunda tıkanırsın.

YöntemKod nerede çalışırNe zaman seçilir

(cloud session)		Bulutta izole bir VM — varsayılan olarak Anthropic tarafından yönetilenRepo GitHub'da ve iş sen telefonu cebe koyduktan sonra da devam etsin istiyorsun
Remote ControlSenin bilgisayarınİş yerel dosya sistemine, kurulu araçlara veya yerel MCP server'lara muhtaç
DispatchSenin bilgisayarın (Desktop uygulaması)Görevi mesaj gibi atıp nasıl koşacağına Dispatch karar versin — Pro veya Max gerekiyor

Bu sayfanın ağırlığı cloud session'da: GitHub bağlantısı, commit ve PR akışı orada. Remote Control'e 10. bölümde, terminalle bulut arasındaki gidiş gelişe 11. bölümde bakıyoruz.

Ayırt edici soru Bilgisayarın kapalı olacaksa cevap her zaman cloud session. Remote Control ve Dispatch senin makineni sürüyor; makine uyursa oturum da bekler.

Bir de karışması kolay olan bir isim benzerliği var: --cloud bulutta oturum açar, --remote-control ise yereldeki oturumu web'den izlenebilir hale getirir. İkisi akraba değil.

Erişim şartı Claude Code on the web research preview'da: Pro, Max ve Team kullanıcıları ile premium seat veya Chat + Claude Code seat'i olan Enterprise kullanıcıları için. Zero Data Retention açık olan organizasyonlar cloud session özelliklerini kullanamıyor. Remote Control ise tüm planlarda var ama Team/Enterprise'da bir Owner açana kadar kapalı.

02 GitHub'ı bağlamanın iki yolu

Cloud session'ın repoyu klonlayıp branch push edebilmesi için GitHub erişimine ihtiyacı var. İki yol da aynı kapıya çıkıyor, seçim nerede olduğuna bağlı.

YöntemNasıl işlerKime uygun
GitHub AppTarayıcıda claude.ai/code açılır, Claude GitHub App yetkilendirilirTarayıcıdan başlayanlar; Auto-fix isteyen ekipler
/web-setupTerminaldeki yerel gh CLI token'ını Claude hesabına senkronlargh zaten kurulu olan geliştiriciler

Tarayıcıdan: üç adım

  • Gir: claude.ai/code adresine Anthropic hesabınla giriş yap.
  • App'i kur: ekrandaki yönlendirmeyle Claude GitHub App'i kur ve repolarına erişim ver.
  • Environment'ı onayla: onboarding senin için Default adında bir cloud environment oluşturur. İlk proje için olduğu gibi bırak.

Cloud session mevcut GitHub repolarıyla çalışıyor; sıfırdan bir proje başlatacaksan önce GitHub'da boş bir repo aç.

Terminalden: /web-setup

gh zaten kuruluysa tarayıcı açmadan halledebilirsin. Sırasıyla:

# 1. gh CLI oturumu (zaten açıksa atla)
gh auth login

Sonra claude içinde — kabukta değil, Claude Code oturumunun içinde:

/login       # claude.ai hesabıyla giriş; API key sayılmıyor
/status      # Login method satırı claude.ai hesabı gösteriyor mu?
/web-setup

Başarılıysa Connected as <github-kullanıcı-adın> yazar ve tarayıcıda claude.ai/code açılır. Cloud environment'ın yoksa Trusted network erişimiyle bir tane oluşturur.

Sık karışan nokta GitHub App'i hangi repolara kurduğun, session'ın hangi repolara erişebildiğini belirlemiyor. Cloud session, bağlı GitHub hesabının görebildiği her repoyu görür. App kurulumu Auto-fix için gereken PR webhook'larını açar; erişim kontrolü değildir. Erişimi daraltmak istiyorsan GitHub tarafında daraltacaksın.

Team ve Enterprise Owner'ları /web-setup'ı claude.ai/admin-settings/claude-code altındaki Quick web setup anahtarıyla kapatabiliyor; kapalıysa komut menüde hiç görünmez.

03 Kutuyu bir kez ayarla: cloud environment

Her cloud session bir cloud environment içinde koşuyor. Environment üç şeyi tutuyor: ağ erişim seviyesi, environment variable'lar ve oturum başlarken çalışan setup script. Onboarding'in açtığı Default environment'ın kendine ait hiçbir yapılandırması yoktur — sadece Trusted ağ erişimi vardır.

Ayar penceresine ulaşmanın yolu: claude.ai/code'da mesaj kutusunun üstündeki satırda, mevcut environment'ın adını gösteren bulut simgesine bas. Ayrı bir ayarlar sayfası veya doğrudan URL'i yok. Oradan Add cloud environment ile yeni açar, mevcut birinin üstüne gelip dişli simgesiyle düzenlersin.

Network access: dört seviye

SeviyeDışarı çıkan bağlantılar
NoneSession'ın ağı üzerinden hiç dış erişim yok
Trusted (varsayılan)Sadece allowlist'teki alan adları: paket registry'leri, GitHub, cloud SDK'ları
FullHer alan adı
CustomKendi listen — istersen varsayılanları da içerecek şekilde

Custom seçtiğinde Allowed domains alanına satır başına bir alan adı yazılır; baştaki *. tüm alt alan adlarını kapsar:

api.example.com
*.internal.example.com
registry.example.com

Varsayılan paket yöneticisi listesini de tutmak istiyorsan Also include default list of common package managers kutusunu işaretle. GitHub trafiği bu allowlist'ten geçmiyor — onun ayrı bir proxy'si var (5. bölüm).

VM'de hazır ne var?

Her session Ubuntu 24.04 / x86_64 üzerinde taze bir VM alıyor ve içinde yaygın toolchain'ler kurulu geliyor: Python (pip, poetry, uv, pytest, ruff), Node.js 20/21/22 (npm, yarn, pnpm), Ruby, PHP 8.4, OpenJDK 21, Go, Rust, GCC/Clang/cmake, Docker, PostgreSQL 16, Redis 7.0, git, jq, ripgrep, tmux. Kesin sürümler için Claude'dan VM'de check-tools komutunu çalıştırmasını isteyebilirsin.

Kaynak tavanları yaklaşık olarak 4 vCPU, 16 GB RAM, 30 GB disk. Ağır build'ler bu sınırı zorlayabilir.

Neyin taşındığına dikkat Cloud session repo'nun taze bir klonundan başlıyor. Repoya commit'lediğin her şey oradadır: CLAUDE.md, .claude/settings.json, .mcp.json, .claude/skills/, .claude/agents/, .claude/commands/. Sadece kendi makinende duran hiçbir şey yoktur: ~/.claude/CLAUDE.md, kullanıcı seviyesindeki skill/agent/command'lar, claude mcp add ile local ya da user scope'a eklediğin MCP server'lar. Yapılandırmanın cloud'da da geçerli olmasını istiyorsan repoya commit'leyeceksin — MCP için claude mcp add --scope project.

Setup script

Kurulu gelmeyen bir şeye ihtiyaç varsa environment'ın Setup script alanına Bash yazarsın; Claude Code başlamadan önce, root olarak çalışır:

#!/bin/bash
apt update && apt install -y gh

Üç kuralı var: sıfırla çıkacak (sıfır dışı çıkış oturumu başlatmaz — kritik olmayan komutlara || true ekle), kabaca beş dakikada bitecek ve kurulumlar için ağ erişimi gerekecek (None seviyesinde paket kurulumu çalışmaz). Script ilk oturumda çalışır, sonra dosya sistemi anlık görüntüsü alınır ve sonraki oturumlar o görüntüden başlar — script'i veya izinli alan adlarını değiştirene ya da cache yaklaşık yedi günde dolana kadar bir daha çalışmaz.

Sır saklama yeri değil Henüz ayrılmış bir secrets store yok. Environment variable'lar ve setup script environment yapılandırmasında duruyor; o environment'ı kullanan herkes okuyabilir. Token koyman gerekiyorsa bunu bilerek koy ve kapsamını dar tut.

04 İlk görev: repo, branch, mod

GitHub bağlıysa ve bir environment varsa geriye üç seçim kalıyor. Hepsi mesaj kutusunun çevresinde, hem tarayıcıda hem telefonda aynı yerde.

  • Repo ve branch: mesaj kutusunun altındaki repo seçiciye bas ve repoyu seç. Her repo bir branch seçici gösterir — varsayılan yerine bir feature branch'ten başlatmak istiyorsan burada değiştir. Tek oturumda birden çok repo ekleyip aralarında çalışabilirsin.
  • Permission mode: yanındaki açılır menü Accept edits'te başlar; Claude değişikliği yapar ve onay beklemeden branch'i push eder. Önce planı görmek istiyorsan Plan'a al. Cloud session'da Manual ve Bypass permissions yok.
  • Görev metni: yaz ve gönder. Claude repoları klonlar, varsa setup script'i çalıştırır ve işe koyulur.

İstem ne kadar somutsa sonuç o kadar iyi. "testleri düzelt" yerine dosyayı ve fonksiyonu adıyla ver, elindeki hata çıktısını yapıştır, semptomu değil beklenen davranışı anlat.

Paralel çalışma Her görev kendi oturumunu ve kendi branch'ini alıyor. Biri bitsin diye beklemene gerek yok — üç ayrı işi aynı anda başlatıp üçünü de ayrı ayrı gözden geçirebilirsin. Fatura tarafında ayrı bir hesaplaşma yok: cloud VM için ek bir ücret alınmıyor, ama paralel görevler rate limit'ten orantılı olarak yiyor.

Hazır doldurulmuş oturum linkleri

claude.ai/code URL'ine query parametresi ekleyerek istemi, repoları ve environment'ı önceden doldurabilirsin. Issue tracker'ına "Claude'a gönder" düğmesi koymak istiyorsan yol bu:

https://claude.ai/code?prompt=Fix%20the%20login%20bug&repositories=acme/webapp

Kullanılabilir parametreler: prompt (kısaltması q), prompt_url (query string'e sığmayacak kadar uzun istemler için), repositories (kısaltması repo, virgülle ayrılmış owner/repo) ve environment. Değerleri URL-encode etmeyi unutma.

05 Commit'i Claude atıyor, proxy kolluyor

Buradaki en kritik zihinsel düzeltme şu: telefonda elle git commit yazmıyorsun. VM'ye kabuk erişimin yok. Tüm komutları Claude çalıştırıyor; sen istemi yazıyorsun, o commit'liyor ve push'luyor.

Bir cloud session'ın akışı şöyle işliyor:

  • Klonla ve hazırla: repo Anthropic'in yönettiği VM'e klonlanır, varsa setup script çalışır.
  • Ağı kur: environment'ın erişim seviyesine göre internet erişimi ayarlanır.
  • Çalış: Claude kodu inceler, değiştirir, testleri koşturur, kendi işini kontrol eder. Bu sırada izleyip yönlendirebilir ya da gidip başka bir şey yapabilirsin.
  • Branch'i push'la: Claude bir durma noktasına geldiğinde branch'i GitHub'a push eder.

Branch push edildiğinde oturum kapanmıyor. PR açmak ve sonraki düzenlemeler aynı konuşmanın içinde devam ediyor.

Kimlik bilgilerin VM'in içine girmiyor

Anthropic'in yönettiği environment'larda tüm GitHub işlemleri ayrı bir proxy üzerinden geçiyor ve gerçek GitHub token'ın session VM'inin dışında kalıyor. Bunun pratikte üç sonucu var:

  • Push koruması: git push yalnızca oturumun o anki çalışma branch'ine karşı çalışıyor. Klonlama, fetch ve PR işlemleri normal seyrinde. Yani bir cloud session, elindeki yetkiyle main'in üstüne yazamıyor.
  • Repo kapsamı: GitHub API ve release asset istekleri yalnızca oturuma bağlı repolara ulaşıyor; bağlı olmayan bir repodan indirmeye kalkan setup script 403 alıyor.
  • GraphQL sınırı: proxy yalnızca pull request akışları için sabitlenmiş bir GraphQL operasyon setine izin veriyor; gerisini This GraphQL query is not enabled for this session diyerek 403'le geri çeviriyor ve REST karşılığını (gh api repos/{owner}/{repo}/...) öneriyor. Sadece GraphQL'de var olan API'ler — örneğin Projects v2 — proxy üzerinden erişilemiyor. Bu kısıt kendi verdiğin GH_TOKEN için de geçerli.

Issue okumak, PR listelemek, diff çekmek, yorum yazmak için oturumda hazır gelen GitHub araçları var; ek kurulum istemiyorlar. GitHub'ın gh CLI'ı ise kurulu gelmiyor — gh release veya gh workflow run gibi bir şey lazımsa setup script'ine apt install -y gh eklersin.

proxy-injected Kendin bir token vermediysen GH_TOKEN ve GITHUB_TOKEN, Claude'un çalıştırdığı komutlarda proxy-injected yer tutucu dizesi olarak okunur; proxy dışarı giden isteklerde gerçek kimliği yerine koyar. gh kendi token'ın olmadan çalışır, ama GITHUB_TOKEN'ı doğrudan okuyan bir script eline kullanılabilir bir token değil bu yer tutucuyu alır. Hangi durumda olduğunu görmek için Claude'a echo $GH_TOKEN çalıştırt.

Commit mesajındaki iz

Claude'un cloud session'da oluşturduğu commit'ler bir Claude-Session: <url> git trailer'ı taşıyor, PR gövdelerinde de oturum linki kendi satırında yer alıyor. Böylece bir reviewer commit'ten oturumun transkriptine gidebiliyor. İstemiyorsan attribution.sessionUrl ayarını false yaparsın.

Linki başka bir yerde — Claude'un yazdığı bir rapor dosyasında, attığı bir mesajda — kullanmak istersen oturum kendi ID'sini CLAUDE_CODE_REMOTE_SESSION_ID değişkeninden okuyabiliyor:

echo "https://claude.ai/code/${CLAUDE_CODE_REMOTE_SESSION_ID/#cse_/session_}"
GitHub şart mı? Repo klonlama ve PR açma GitHub gerektiriyor. Team ve Enterprise planlarında self-hosted GitHub Enterprise Server destekleniyor. GitLab, Bitbucket ve GitHub'da olmayan repolar --cloud ile yerel bundle olarak gönderilebiliyor, ama o oturum sonucu remote'a geri push edemiyor.

06 Diff'te satıra dokun, lafını orada söyle

Claude durduğunda oturumda +42 -18 gibi bir diff göstergesi belirir; üstüne bastığında solda dosya listesi, sağda değişiklikler açılır. Telefonda da aynı görünüm.

Asıl işe yarayan kısım satır içi yorumlar: diff'te bir satır seç, geri bildirimini yaz, Enter'a bas. Yorumlar bir sonraki mesajını gönderene kadar birikir, sonra mesajınla birlikte paketlenir. Claude ana talimatının yanında "at src/auth.ts:47, don't catch the error here" bilgisini de görür — yani sorunun nerede olduğunu ayrıca tarif etmen gerekmez.

Telefonda en çok işe yarayan alışkanlık Uzun bir düzeltme mesajı yazmak yerine diff'te üç dört satıra dokunup kısa notlar bırak, sonra tek bir "bunları düzelt" mesajı gönder. Küçük ekranda hem daha hızlı hem daha isabetli.

Bir teknik ayrıntı: Claude Code bu diff'leri ham git blob içeriğinden hesaplıyor, dolayısıyla repoda tanımlı diff driver'ları ve textconv filtreleri burada devreye girmiyor.

07 Create PR — ve iş orada bitmiyor

Diff istediğin hale geldiğinde diff görünümünün üstündeki Create PR düğmesine basarsın. Üç seçenek çıkar: tam PR olarak açmak, draft olarak açmak veya başlık ve açıklaması üretilmiş halde GitHub'ın compose sayfasına atlamak.

PR açıldıktan sonra oturum yaşamaya devam ediyor. CI çıktısını ya da reviewer yorumunu sohbete yapıştırıp Claude'dan halletmesini isteyebilirsin — aynı konuşmada, aynı branch üzerinde.

  • Telefondan tipik akış: Code sekmesi → repo + branch seç → görevi yaz → (bekle) → diff göstergesine bas → satır yorumları → "şunları düzelt" → Create PR → draft.
  • Masaüstünde devam: aynı oturum claude.ai/code'da duruyor; istersen 11. bölümdeki --teleport ile terminale çekersin.

08 CI kırıldığında Claude uyansın

Auto-fix, Claude'un bir pull request'i izleyip CI hatalarına ve review yorumlarına kendiliğinden cevap vermesi demek. Claude PR'ın GitHub aktivitesine abone oluyor; bir check düşerse veya biri yorum bırakırsa inceliyor ve düzeltme netse push ediyor.

Açmanın yolu, PR'ın nereden geldiğine ve elindeki cihaza göre değişiyor:

  • Web'de açılmış PR'lar: CI durum çubuğunu aç ve Auto-fix'i seç.
  • Terminalden: PR'ın branch'indeyken /autofix-pr çalıştır — Claude Code açık PR'ı gh ile bulur, bir web oturumu açar ve auto-fix'i tek adımda devreye alır.
  • Mobil uygulamadan: Claude'a söyle — "bu PR'ı izle, CI hatalarını ve review yorumlarını düzelt" gibi.
  • Herhangi bir mevcut PR: PR URL'ini oturuma yapıştır ve auto-fix etmesini iste.

Kapatmak için web oturumundaki CI durum çubuğunda Auto-fix anahtarını temizlersin ya da Claude'a izlemeyi bırakmasını söylersin. PR başına bir anahtar, global bir ayar değil.

Claude gelen her olayı tek tek değerlendiriyor: emin olduğu ve daha önceki talimatlarla çelişmeyen düzeltmeleri yapıp push ediyor, birden çok yoruma açık ya da mimari ağırlığı olan istekleri sana soruyor, tekrar eden veya işlem gerektirmeyen olayları oturumda not düşüp geçiyor.

İki tuzak Merge conflict'i kendiliğinden fark etmiyor: base branch ilerleyip çakışma oluştuğunda GitHub webhook üretmediği için auto-fix tepki veremiyor — oturumu açıp rebase istemen gerekiyor. Yorumlar senin hesabından gidiyor: Claude review thread'lerine senin GitHub hesabınla cevap yazıyor (her cevap Claude Code'dan geldiğine dair etiket taşıyor). Repon issue_comment olayıyla tetiklenen otomasyon kullanıyorsa — Atlantis, Terraform Cloud, özel Actions — bu yorumlar o iş akışlarını çalıştırabilir. Bir PR yorumunun altyapı deploy ettiği repolarda auto-fix'i açma.

Auto-fix, PR webhook'larını alabilmek için Claude GitHub App'in repoda kurulu olmasını gerektiriyor. /web-setup ile bağlandıysan App'i ayrıca kurman gerekir.

09 Code sekmesi cebinde

Claude Code'un ayrı bir mobil uygulaması yok. iOS ve Android'deki Claude uygulaması, Claude Code oturumları için bir istemci; cloud session'lar da Remote Control oturumları da aynı Code sekmesinde yaşıyor.

  • Uygulamayı kur: iOS veya Android. iPad'de de aynı iOS uygulaması kullanılıyor. Bir Claude Code oturumunda /mobile yazarsan indirme QR kodu çıkar — /ios ve /android da aynı işi görüyor.
  • Aynı hesapla gir: Claude Code'da kullandığın claude.ai hesabı ve organizasyonu. Cloud session ve Remote Control claude.ai hesabı istiyor; Console API key'i veya Bedrock gibi üçüncü taraf sağlayıcılar bu kapıdan geçmiyor.
  • Code sekmesini aç: oturumlarına ulaşmak için gezinmede Code'a dokun. Telefonda doğrudan yeni oturum açmak için claude.ai/code/new. Code sekmesi görünmüyorsa planın veya organizasyonun bu özellikleri kapsamıyor olabilir.

Oturumlar cihazlar arasında taşınıyor: laptop'ta başlattığın görev telefondan incelemeye hazır bekliyor, telefondan başlattığın da masana döndüğünde orada duruyor. Sekmeyi kapatmak, uygulamayı kapatmak oturumu durdurmuyor — Claude o anki görevi bitirene kadar arka planda çalışmaya devam edip sonra boşta bekliyor.

Oturumu paylaşmak

Enterprise ve Team hesaplarında görünürlük seçenekleri Private ve Team; Team seçeneği oturumu claude.ai organizasyonundaki diğer üyelere açıyor ve repo erişimi doğrulaması varsayılan olarak açık geliyor. Max ve Pro hesaplarında seçenekler Private ve Public — Public, claude.ai'ye giriş yapmış herkesin oturumu görebilmesi demek ve repo erişimi doğrulaması varsayılan olarak kapalı.

Paylaşmadan önce bak Oturumlar private repolardan gelen kod ve kimlik bilgileri içerebiliyor. Public'e almadan önce içeriğe göz at. Alıcılardan repo erişimi istemek veya adını gizlemek için Settings > Claude Code > Sharing settings.

10 Makinen açık kalacaksa: Remote Control

Cloud session'ın bilmediği bir şey var: senin yerel dosya sistemin, kurulu araçların, @ ile tamamlanan dosya yolların ve yerel MCP server'ların. İşin bunlara muhtaçsa doğru yol Remote Control — kod senin makinende çalışmaya devam ediyor, telefon ve tarayıcı o oturuma açılan bir pencere oluyor.

Başlatmanın üç yolu var:

# Sunucu modu: terminal açık kalır, uzak bağlantı bekler
claude remote-control

# Normal interaktif oturum + Remote Control (kısası --rc)
claude --remote-control "My Project"

Zaten açık bir oturumu uzaktan sürdürmek istiyorsan oturumun içinde /remote-control (kısası /rc) yazman yeterli; o ana kadarki konuşma geçmişi taşınıyor.

Telefondan bağlanmanın üç yolu: oturum URL'ini herhangi bir tarayıcıda açmak, terminaldeki QR kodu okutmak (claude remote-control'da boşluk tuşu QR kodunu açıp kapatıyor) ya da uygulamada Code sekmesinden oturumu listeden seçmek. Remote Control oturumları listede yeşil noktalı bir bilgisayar simgesiyle görünüyor.

Bildirim gelsin

Remote Control aktifken Claude telefonuna push bildirimi gönderebiliyor — tipik olarak uzun süren bir iş bittiğinde veya senden bir karar gerektiğinde. İstemin içinde notify me when the tests finish gibi açıkça da isteyebilirsin. Kurulum tarafında iki anahtar var; terminalde /config çalıştırıp Push when Claude decides (kendiliğinden bildirim) ve Push when actions required (izin istemleri ve sorular) seçeneklerinden birini ya da ikisini açarsın.

Yerel süreç ölürse oturum ölür Remote Control yerel bir süreç olarak çalışıyor. Terminali kapatırsan, VS Code'dan çıkarsan veya claude sürecini durdurursan oturum biter. SSH'tan koptuktan sonra da yaşamasını istiyorsan tmux ya da screen içinde başlat. Makine uyanıkken ağa kabaca 10 dakikadan uzun erişemezse oturum zaman aşımına uğrayıp çıkıyor.

Bildirim gelmiyorsa: /config ekranında No mobile registered yazıyorsa telefonda Claude uygulamasını açıp push token'ını tazelet. iOS'ta Focus modları ve bildirim özetleri push'u geciktirebiliyor; Android'de agresif pil optimizasyonu aynı işi yapıyor.

11 Terminal ile bulut arasında gidip gelmek

Bu ikisi CLI'ın claude.ai'deki aynı hesaba giriş yapmış olmasını gerektiriyor.

Terminalden buluta: --cloud

claude --cloud "Fix the authentication bug in src/auth/login.ts"

Bu komut claude.ai'de yeni bir cloud session açıyor. Dikkat edilecek nokta: bulut VM'i yerel checkout'unu değil, bulunduğun dizinin GitHub remote'unu ve o anki branch'ini klonluyor — yerel commit'lerin varsa önce push et. --cloud tek seferde tek repoyla çalışıyor. İlerlemeyi /tasks ile izler, oturumu claude.ai'de veya mobil uygulamada açıp doğrudan konuşursun.

Zaten koşan bir oturuma her makineden mesaj gönderebilirsin:

claude -p "testleri de çalıştır" --cloud <session-id>

Bu biçim mesajı kuyruğa atıp çıkıyor, cevabı beklemiyor. -p olmadan claude --cloud <session-id> terminalini oturuma bağlıyor — ama bu interaktif bağlanma kademeli açılıyor, hesabında yoksa Attaching to an existing cloud session is not enabled for your account hatası alırsın; kuyruğa atan biçim bundan etkilenmiyor.

İyi çalışan desen Karmaşık işlerde planı yerelde kur, uygulamayı buluta ver: claude --permission-mode plan ile yaklaşımı birlikte belirle, planı repoya commit'leyip push et, sonra claude --cloud "Execute the migration plan in docs/migration-plan.md" de. Strateji sende kalır, yürütme otonom olur.

Buluttan terminale: --teleport

Bulutta başlayan bir işi makinende bitirmek istediğinde:

claude --teleport                # interaktif oturum seçici
claude --teleport <session-id>   # doğrudan o oturum

Açık bir CLI oturumunun içindeysen /teleport (veya /tp) aynı seçiciyi açıyor; /tasks listesinde t tuşu da teleport ediyor. Web arayüzünde oturum menüsünden Open in > Terminal yapıştırılacak komutu veriyor.

Teleport ederken Claude doğru repoda olduğunu doğruluyor, cloud oturumunun branch'ini fetch edip checkout ediyor ve tüm konuşma geçmişini terminale yüklüyor. Ön koşullar: çalışma dizinin temiz olacak (kirliyse stash'lemeni ister), fork değil aynı reponun bir checkout'unda olacaksın, branch remote'a push edilmiş olacak ve aynı claude.ai hesabıyla giriş yapmış olacaksın.

Teleport tek yönlü --teleport bulut oturumunu terminale çeker; mevcut bir terminal oturumunu web'e itemezsin. Ayrıca teleport'tan sonra terminal oturumun kendi kopyası olur — orada yaptığın yeni iş claude.ai'deki veya mobil uygulamadaki cloud oturumunda görünmez. Teleport ettikten sonra da telefondan yönlendirmeye devam etmek istiyorsan yerel oturumda /remote-control başlat. Bir de --teleport, --resume değildir: --resume bu makinenin yerel geçmişini açar, bulut oturumlarını listelemez.

Session creation failed veya provisioning'de takılmaVM ayrılamamış. status.claude.com'a bak, bir dakika sonra tekrar dene, reponun erişilebilir olduğunu doğrula.
