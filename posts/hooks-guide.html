01 Hook neden farklı

Claude'a talimat vermenin birçok yolu var: CLAUDE.md, rules, skills, output styles. Hepsinin ortak özelliği şu — bunlar öneridir. Model çoğu zaman uyar, ama uzun bir oturumda, baskı altında ya da okuduğu bir dosyadaki yönlendirme yüzünden atlayabilir.

Hook'lar bu kategoride değil. Hook, Claude'un yaşam döngüsündeki belirli bir anda harness'in çalıştırdığı koddur. Çalışıp çalışmayacağına model karar vermez, hatta çalıştığından haberi bile olmayabilir.

Ayrım tek cümlede "Şunu yapmayı unutma" bir talimattır. "Şu olduğunda hep şu çalışır" bir hook'tur. Güvenilir biçimde tekrarlanması gereken her cümle aslında bir hook'tur.

Hook'un tipik işleri:

  • Zorlamak: dosya düzenlemesinden sonra formatlayıcıyı çalıştır.
  • Engellemek: korumalı dosyalara yazmayı ya da tehlikeli komutları durdur.
  • Bilgilendirmek: Claude beklemeye geçtiğinde masaüstü bildirimi at.
  • Context enjekte etmek: oturum başında ya da compaction sonrası kritik bilgiyi geri ver.
  • Kayıt tutmak: her Bash komutunu veya her config değişikliğini log'la.
Sessiz çalışan hook, olmayan hook gibidir Bir hook iş yapıp sonucu geri döndürmezse Claude o işten habersiz kalır. PreCompact'te konuşmayı bir dosyaya yedeklediysen, Claude o yedeğin nerede olduğunu bilmez. Bilmesini istiyorsan çıktıyı açıkça geri döndürmen gerekir.

02 İlk hook'un

Hook, bir ayar dosyasındaki JSON bloğudur. Aşağıdaki örnek, Claude senden bir şey beklemeye geçtiğinde masaüstü bildirimi gönderir — terminale bakmadan başka işe dönebilirsin.

// ~/.claude/settings.json — macOS
{
  "hooks": {
    "Notification": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "osascript -e 'display notification \"Claude bekliyor\" with title \"Claude Code\"'"
          }
        ]
      }
    ]
  }
}

Windows'ta aynı hook şöyle olur:

"command": "powershell.exe -Command \"[System.Reflection.Assembly]::LoadWithPartialName('System.Windows.Forms'); [System.Windows.Forms.MessageBox]::Show('Claude bekliyor', 'Claude Code')\""

Linux'ta: notify-send 'Claude Code' 'Claude bekliyor'

Doğrula

/hooks yazınca tüm event'lerin listesi açılır; yapılandırılmış olanların yanında sayı görünür. Notification'ı seçtiğinde event, matcher, tür, kaynak dosya ve komut görünür.

/hooks salt okunurdur Menüden hook ekleyemez, düzenleyemez veya silemezsin — yalnızca yapılandırmayı görüntülemek için. Değişiklikleri ayar dosyasında yaparsın (ya da Claude'a yaptırırsın).
Zaten hooks bloğun varsa Yeni event'i mevcut hooks nesnesinin içine kardeş anahtar olarak ekle; bloğun tamamını değiştirme. Her event adı tek bir hooks nesnesinin içinde bir anahtardır.

03 Yapılandırma anatomisi

Yapı üç katmanlıdır ve ilk bakışta kafa karıştırıcı gelen kısım, hooks kelimesinin iki farklı seviyede geçmesidir: dıştaki event haritası, içteki ise o gruba bağlı handler listesi.

{
  "hooks": {                        // 1. event haritası
    "PreToolUse": [
      {
        "matcher": "Bash",          // 2. grup: hangi durumlarda
        "hooks": [                   // 3. handler'lar: ne çalışacak
          {
            "type": "command",
            "command": "./scripts/kontrol.sh",
            "if": "Bash(git *)",
            "timeout": 30,
            "statusMessage": "Politika kontrol ediliyor…"
          }
        ]
      }
    ]
  }
}
AlanZorunluNe yapar
typeevetcommand, http, mcp_tool, prompt veya agent
commandcommand içinÇalıştırılacak komut ya da script yolu
argshayırVerilirse exec form'a geçilir: shell yok, argümanlar doğrudan geçilir
ifhayırPermission rule sözdizimiyle filtre: Bash(git *), Edit(*.ts). Yalnızca tool event'lerinde
timeouthayırSaniye cinsinden iptal süresi
statusMessagehayırHook çalışırken gösterilen özel spinner metni

exec form vs shell form

args yazarsan komut PATH üzerinde bir çalıştırılabilir olarak çözümlenir ve argümanlar shell'e uğramadan geçer. Yazmazsan komut bir shell'e verilir (macOS/Linux'ta sh -c, Windows'ta Git Bash, Git Bash kurulu değilse PowerShell) ve pipe, &&, glob, değişken genişletme kullanabilirsin. Tırnak sorunlarından tamamen kaçınmak istiyorsan "args": [] ekleyip exec form'a geç.

Yol yer tutucuları

  • ${CLAUDE_PROJECT_DIR} — proje kökü
  • ${CLAUDE_PLUGIN_ROOT} — plugin kurulum klasörü
  • ${CLAUDE_PLUGIN_DATA} — plugin kalıcı veri klasörü

Script'e göreli yolla erişmeye çalışma; hook'un çalışma dizini beklediğin yer olmayabilir.

Zaman aşımı varsayılanları

TürVarsayılanİstisna
command, http, mcp_tool10 dakikaUserPromptSubmit'te 30 sn, MessageDisplay'de 10 sn
prompt30 saniye—
agent60 saniye—
SessionEnd (her tür)1,5 saniye ortak bütçeDaha uzun timeout yazarsan bütçe 60 sn'ye kadar yükselir

04 Hook nerede yaşar

Dosyanın konumu hook'un kapsamını ve paylaşılabilirliğini belirler.

KonumKapsamPaylaşılabilir mi
~/.claude/settings.jsonTüm projelerinHayır, makinene özel
.claude/settings.jsonTek projeEvet, repoya commit edilir
.claude/settings.local.jsonTek projeHayır, gitignore'lanır
Managed policy settingsKurum geneliEvet, admin denetiminde
Plugin hooks/hooks.jsonPlugin etkinkenEvet, plugin'le birlikte gelir
Skill / agent frontmatterO bileşen aktifkenEvet, bileşen dosyasında

Farklı seviyelerdeki hook'lar birleşir, birbirini değiştirmez. Ayar dosyalarını Claude Code çalışırken düzenlersen file watcher değişikliği normalde kendiliğinden alır.

disableAllHooks'un kapsamı dar "disableAllHooks": true yalnızca kendi bulunduğu ayar seviyesindeki hook'ları kapatır. Managed settings'te tanımlı hook'lar, orada da ayarlanmadıkça çalışmaya devam eder.

05 Event'lerin tamamı

Doğru hook'u yazmanın ilk adımı doğru anı seçmek. Event'ler yaşam döngüsündeki yerlerine göre gruplanmış halde:

Oturum

EventNe zaman ateşlenir
SessionStartOturum başladığında veya devam ettirildiğinde
Setup--init-only ile, ya da -p modunda --init/--maintenance ile başlatıldığında. CI ve script'lerde tek seferlik hazırlık için
SessionEndOturum sonlandığında

Prompt ve turn

EventNe zaman ateşlenir
UserPromptSubmitPrompt'u gönderdiğinde, Claude işlemeden önce
UserPromptExpansionYazdığın bir komut prompt'a genişlediğinde. Genişlemeyi engelleyebilir
MessageDisplayAsistan mesajı ekrana yazılırken
StopClaude yanıtını bitirdiğinde
StopFailureTurn bir API hatasıyla bittiğinde. Çıktısı ve exit kodu yok sayılır

Tool çağrıları

EventNe zaman ateşlenir
PreToolUseBir tool çağrısı çalışmadan önce. Engelleyebilir
PermissionRequestBir tool çağrısı izin kararı gerektirdiğinde
PermissionDeniedÇağrı auto mode sınıflandırıcısı tarafından reddedildiğinde. {retry: true} ile modele tekrar deneyebileceğini söylersin
PostToolUseTool çağrısı başarılı olduktan sonra
PostToolUseFailureTool çağrısı başarısız olduktan sonra
PostToolBatchParalel tool çağrılarından oluşan bir grup tamamlandığında, bir sonraki model çağrısından önce

Subagent ve task

EventNe zaman ateşlenir
SubagentStart / SubagentStopBir subagent kurulduğunda / bitirdiğinde
TaskCreated / TaskCompletedBir task oluşturulurken / tamamlanmış işaretlenirken

Context, config ve dosya sistemi

EventNe zaman ateşlenir
PreCompact / PostCompactCompaction öncesi / sonrası

Paralel çalışırlar Bir event ateşlendiğinde eşleşen tüm hook'lar paralel çalışır. Aynı handler'ı birden çok ayar dosyasında tanımlarsan bir kez çalışır; plugin'in ya da skill'in kendi kopyası ayrı sayılır. Bir hook'un deny dönmesi kardeş hook'ların çalışmasını durdurmaz — birinin engellemesine güvenip diğerinin yan etkisini önlediğini varsayma.

06 matcher ve if

Matcher yazmazsan hook, event'in her gerçekleşmesinde çalışır. Her event farklı bir alan üzerinde filtreler:

EventNeyi filtrelerÖrnek değerler
PreToolUse, PostToolUse, PermissionRequest…Tool adıBash, Edit|Write, mcp__.*
SessionStartOturumun nasıl başladığıstartup, resume, clear, compact, fork
SessionEndBitiş sebebiclear, resume, logout, prompt_input_exit
NotificationBildirim türüpermission_prompt, idle_prompt, auth_success
SubagentStart, SubagentStopAgent türüExplore, Plan, general-purpose, özel adlar
PreCompact, PostCompactCompaction'ı ne tetikledimanual, auto
ConfigChangeYapılandırma kaynağıuser_settings, project_settings, policy_settings, skills
FileChangedİzlenecek dosya adları.envrc|.env (yalnızca birebir eşleşme)
UserPromptSubmit, Stop, PostToolBatch, CwdChanged…Matcher desteklemezHer zaman ateşlenir

Desen sözdizimi

  • "*", "" veya alan hiç yok — hepsiyle eşleşir
  • "Bash" — birebir eşleşme
  • "Edit|Write" — çoklu eşleşme (v2.1.191'den itibaren virgül de aynı işi görür)
  • "mcp__github__.*" — regex; yalnızca harf, rakam, _, -, boşluk, , ve | içeren desenler birebir eşleşme listesi sayılır, bunların dışında bir karakter geçen her desen bağlanmamış (unanchored) JavaScript regex olarak değerlendirilir — Edit.* hem Edit'i hem NotebookEdit'i yakalar, tam eşleşme için ^Edit$ yaz

MCP tool'ları mcp__<sunucu>__<tool> biçiminde adlandırılır; bir sunucunun tüm tool'larını yakalamak için mcp__github__.* yazarsın.

Matcher büyük/küçük harfe duyarlı bash yazarsan Bash tool'unu yakalamaz ve hook hiç çalışmaz — hata da vermez. Hook'un neden ateşlenmediğini ararken ilk bakılacak yer burasıdır.

if: tool adının ötesine geçmek

matcher grup seviyesinde ve yalnızca tool adına bakar. if ise permission rule sözdizimiyle argümanları da filtreler; eşleşme yoksa hook süreci hiç başlatılmaz.

{
  "type": "command",
  "if": "Bash(git *)",
  "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/git-politikasi.sh"
}
if deseniBash komutuÇalışır mıNeden
Bash(git *)git pushevetKomut adı eşleşiyor
Bash(git *)npm test && git pushevetHer alt komut ayrı denetlenir
Bash(git *)echo $(git log)evet$() ve backtick içindekiler de denetlenir
Bash(git *)echo $(date)hayırEşleşen alt komut yok
İki tuzak if yalnızca tool event'lerinde çalışır (PreToolUse, PostToolUse, PostToolUseFailure, PermissionRequest, PermissionDenied); başka bir event'e eklersen hook hiç çalışmaz. Ayrıca filtre fail-open'dır: komut ayrıştırılamazsa hook yine de çalışır. Kesin bir izin/yasak gerekiyorsa bunu if ile değil permission sistemiyle kur.
Bash dosya da değiştirebilir Edit|Write matcher'ı, Claude'un Bash ile yaptığı dosya değişikliklerini görmez. Her değişikliği yakalaman gerekiyorsa (denetim, uyumluluk) turn başına bir kez çalışan bir Stop hook'uyla çalışma ağacını tara.

07 Girdi, çıktı, exit kodu

Hook, Claude Code ile dört kanal üzerinden konuşur: stdin (olay verisi), stdout, stderr ve exit kodu.

Girdi

Event ateşlendiğinde olay verisi script'in stdin'ine JSON olarak yazılır. Her event ortak alanlar (session_id, cwd, hook_event_name, transcript_path, permission_mode) taşır, üstüne kendine özel alanları ekler:

{
  "session_id": "abc123",
  "cwd": "/Users/sarah/myproject",
  "hook_event_name": "PreToolUse",
  "tool_name": "Bash",
  "tool_input": { "command": "npm test" }
}

UserPromptSubmit bunun yerine prompt metnini, SessionStart ise source alanını alır. Subagent içinde çalışan hook'lara ayrıca agent_id ve agent_type gelir.

Exit kodu

ExitAnlamıNe olur
0İtiraz yokEylem normal akışta devam eder. stdout JSON olarak ayrıştırılır
2Engelleyici hataEylem engellenir; stderr Claude'a geri bildirim olarak gider. stdout yok sayılır
diğerEngellemeyen hataEylem devam eder; transkriptte hata notu ve stderr'in ilk satırı görünür
 
#!/bin/bash
INPUT=$(cat)
COMMAND=$(echo "$INPUT" | jq -r '.tool_input.command')

if echo "$COMMAND" | grep -q "drop table"; then
  echo "Engellendi: tablo silme yasak" >&2   # stderr = Claude'un gördüğü gerekçe
  exit 2                                    # 2 = engelle
fi

exit 0  # 0 = karar yok; normal izin akışı devam eder
Exit 0 onay değildir Bir PreToolUse hook'unun 0 dönmesi tool çağrısını onaylamaz; sadece "itirazım yok" demektir. Normal izin akışı yine işler. Onaylamak istiyorsan JSON çıktı yazman gerekir.
Context'e metin enjekte etmek UserPromptSubmit, UserPromptExpansion ve SessionStart hook'larında 0 ile çıkarsan stdout'a yazdığın her şey Claude'un context'ine eklenir. Diğer event'lerde stdout böyle davranmaz.

Engelleme hangi event'te işe yarar

EventExit 2'nin etkisi
PreToolUseTool çağrısını engeller
PermissionRequestİzni reddeder
UserPromptSubmit, UserPromptExpansionPrompt'un işlenmesini engeller
Stop, SubagentStop, TeammateIdleDurmayı/boşa geçmeyi engeller
TaskCreated, TaskCompletedİşlemi geri alır veya engeller
ConfigChange, PreCompactDeğişikliği / compaction'ı engeller
PostToolBatchBir sonraki model çağrısından önce agentic döngüyü durdurur
PostToolUse, PostToolUseFailureEngelleyemez — tool zaten çalıştı; stderr yalnızca Claude'a geri bildirim olarak gösterilir
SessionStart, Setup, Notification ve diğerleriEngellemez; stderr gösterilir, akış sürer

08 Yapılandırılmış JSON çıktı

Exit kodları yalnızca "engelle" ya da "sus" demeni sağlar. Daha ince kontrol için 0 ile çık ve stdout'a JSON yaz.

İkisini karıştırma Ya exit 2 + stderr, ya exit 0 + JSON. Exit 2 verdiğinde stdout'taki JSON yok sayılır — hook'unun neden dinlenmediğini ararken sık karşılaşılan sebeplerden biri budur.

Her event'te geçerli alanlar

AlanEtkisi
continue: falseClaude'u tamamen durdurur
stopReasoncontinue: false ile gösterilen mesaj
suppressOutputstdout'u transkriptte gizler
systemMessageKullanıcıya gösterilen uyarı

PreToolUse: izin kararı

{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "deny",
    "permissionDecisionReason": "grep yerine rg kullan"
  }
}

permissionDecision değerleri: allow, deny, ask, defer. Aynı event'te birden çok hook karar dönerse en kısıtlayıcısı uygulanır: deny → defer → ask → allow. additionalContext metinleri ise hepsinden toplanıp Claude'a birlikte verilir.

Tool argümanını yeniden yazmak

updatedInput ile çağrının argümanlarını değiştirebilirsin — örneğin tehlikeli bir komutu güvenli sürümüyle takas etmek için.

Tek yazar kuralı Birden çok PreToolUse hook'u aynı çağrıya updatedInput döndürdüğünde hangi girdinin geçerli olacağı tanımlı değildir; hook'lar paralel çalışır ve doküman bu çakışma için bir çözümleme kuralı vermez. Aynı tool'un girdisini birden fazla hook'un değiştirmesine izin verme. (permissionDecision çakışmasının aksine: orada sıra tanımlıdır.)

Diğer event'lerin karar biçimi

  • Üst seviye decision: UserPromptSubmit, UserPromptExpansion, PostToolUse, PostToolUseFailure, PostToolBatch, Stop, SubagentStop, ConfigChange, PreCompact — {"decision": "block", "reason": "…"}
  • Exit kodu ya da continue: false: TeammateIdle, TaskCreated, TaskCompleted — üst seviye decision almazlar
  • Yalnızca context: SessionStart, Setup, SubagentStart — additionalContext döner, engelleyemez
  • PermissionRequest: hookSpecificOutput.decision içinde behavior: "allow" | "deny"

09 command dışındaki türler

Çoğu hook "type": "command"'dur, ama dört tür daha var ve her biri farklı bir problemi çözer.

TürNe yaparNe zaman
commandShell komutu çalıştırırVarsayılan. Deterministik kural, script, CLI aracı
httpOlay verisini bir URL'e POST ederMerkezi bir politika servisi; birden çok makinede aynı kural
mcp_toolBağlı bir MCP sunucusundaki tool'u çağırırDoğrulama zaten bir MCP tool'u olarak varsa
promptTek turluk LLM değerlendirmesi (varsayılan Haiku)Karar kural değil muhakeme gerektiriyorsa
agentTool erişimi olan bir subagent kurarDoğrulama için dosya okumak/komut çalıştırmak gerekiyorsa

prompt hook: "bu iş gerçekten bitti mi?"

{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "prompt",
            "prompt": "Tüm görevler tamamlandı mı? Değilse {\"ok\": false, \"reason\": \"eksik kalanlar\"} döndür."
          }
        ]
      }
    ]
  }
}

Model yalnızca bir evet/hayır kararı döner: {"ok": true} ise akış sürer, {"ok": false} ise event'e göre davranış değişir — Stop ve SubagentStop'ta reason Claude'a geri beslenir ve çalışmaya devam eder.

http hook

{
  "type": "http",
  "url": "http://localhost:8080/validate",
  "headers": { "Authorization": "Bearer $API_TOKEN" },
  "allowedEnvVars": ["API_TOKEN"]
}

Yanıt gövdesi, command hook'larıyla aynı JSON biçimini kullanır. Yalnızca allowedEnvVars'ta sayılan değişkenler header'lara enjekte edilir.

http hook sessizce açılır 2xx olmayan yanıtlar, bağlantı hataları ve zaman aşımları engellemeyen hata sayılır — yani servisin çökmesi guardrail'ini sessizce devre dışı bırakır. Engellemek istiyorsan 2xx ile birlikte decision: "block" ya da permissionDecision: "deny" dönmelisin.
agent hook deneyseldir type: "agent" deneysel; davranışı ve yapılandırması değişebilir. Üretim akışlarında command hook'larını tercih et.

10 Altı örnek senaryo

Her biri farklı bir event ve farklı bir mekanizma kullanıyor. Önce durum, sonra yapılandırma, sonra neden böyle.

Senaryo 1 — Format tutarlılığı modele bırakılmasın

Durum: CLAUDE.md'de "prettier çalıştır" yazıyor ama bazen çalışıyor, bazen çalışmıyor.

// .claude/settings.json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "jq -r '.tool_input.file_path' | xargs npx prettier --write"
          }
        ]
      }
    ]
  }
}
  • PostToolUse çünkü dosya yazıldıktan sonra formatlanır.
  • Matcher Edit|Write: her tool çağrısında değil, sadece dosya yazanlarda.
  • Hook girdiyi stdin'den alır; jq sadece dosya yolunu çıkarıp prettier'a geçer.

Senaryo 2 — Korumalı dosyalara dokunulmasın

Durum: .env, package-lock.json ve .git/ altındaki hiçbir şey değişmemeli. Talimat yazmak yetmiyor.

#!/bin/bash
# .claude/hooks/protect-files.sh

INPUT=$(cat)
FILE_PATH=$(echo "$INPUT" | jq -r '.tool_input.file_path // empty')

PROTECTED=(".env" "package-lock.json" ".git/")

for p in "${PROTECTED[@]}"; do
  if [[ "$FILE_PATH" == *"$p"* ]]; then
    echo "Engellendi: $FILE_PATH korumalı desen '$p' ile eşleşiyor" >&2
    exit 2
  fi
done

exit 0
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/protect-files.sh" }
        ]
      }
    ]
  }
}
  • Exit 2 çağrıyı engeller ve stderr'deki gerekçe Claude'a gider — böylece başka bir yol denemesi gerektiğini anlar, körlemesine tekrar denemez.
  • macOS/Linux'ta chmod +x zorunlu; çalıştırılamayan script hiçbir şeyi engellemez.
  • $CLAUDE_PROJECT_DIR kullan — hook'un çalışma dizini beklediğin yer olmayabilir.

Senaryo 3 — Compaction sonrası kritik bilgi kaybolmasın

Durum: Uzun oturumlarda context sıkıştırılıyor ve Claude proje konvansiyonlarını unutuyor.

{
  "hooks": {
    "SessionStart": [
      {
        "matcher": "compact",
        "hooks": [
          {
            "type": "command",
            "command": "echo 'Hatırlatma: npm değil bun. Commit öncesi bun test. Sprint: auth refactor.'"
          }
        ]
      }
    ]
  }
}
  • SessionStart + compact matcher'ı: yalnızca compaction sonrasında.
  • Bu event'te stdout doğrudan context'e eklenir — hook'un tüm marifeti bu.
  • echo yerine git log --oneline -5 gibi dinamik bir komut da koyabilirsin. Her oturumda sabit kalacak bilgi içinse hook değil CLAUDE.md doğru yerdir.

Senaryo 4 — Her Bash komutu kayda geçsin

Durum: Claude'un ne çalıştırdığını sonradan denetlemek istiyorsun.

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "command": "jq -r .tool_input.command >> ~/.claude/bash.log" },
          { "type": "command", "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/block-rm-rf.sh" }
        ]
      }
    ]
  }
}
  • Aynı gruba iki handler koyabilirsin; ikisi de paralel çalışır.
  • İkinci hook exit 2 ile reddederse çağrı engellenir — ama log yine yazılmıştır, çünkü birinci hook zaten çalıştı. Engellemenin diğer hook'un yan etkisini iptal ettiğini varsayma.

Senaryo 5 — Plan onayı her seferinde sorulmasın

Durum: Plan hazır olduğunda çıkan onay diyaloğunu her defasında sen tıklıyorsun.

{
  "hooks": {
    "PermissionRequest": [
      {
        "matcher": "ExitPlanMode",
        "hooks": [
          {
            "type": "command",
            "command": "echo '{\"hookSpecificOutput\": {\"hookEventName\": \"PermissionRequest\", \"decision\": {\"behavior\": \"allow\"}}}'"
          }
        ]
      }
    ]
  }
}
  • Burada exit kodu değil JSON karar gerekir; otomatik onay ancak böyle verilir.
  • Matcher'ı olabildiğince dar tut. Boş bırakmak veya .* yazmak dosya yazma ve shell komutları dahil her izin sorusunu otomatik onaylar.

Senaryo 6 — Testler geçmeden turn bitmesin

Durum: Claude "bitti" deyip duruyor, ama testlerin gerçekten geçtiğini doğrulamak dosya okumayı ve komut çalıştırmayı gerektiriyor.

{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "agent",
            "prompt": "Tüm unit testlerin geçtiğini doğrula. Test suite'ini çalıştır ve sonucu kontrol et. $ARGUMENTS",
            "timeout": 120
          }
        ]
      }
    ]
  }
}
  • prompt hook'u tek LLM çağrısıdır ve dosya okuyamaz; burada doğrulama çalıştırma gerektirdiği için agent seçildi.
  • $ARGUMENTS yer tutucusu hook girdisinin JSON'ıyla değiştirilir.
  • Varsayılan 60 saniye test suite'i için kısa kalabilir; timeout yükseltildi.
Stop hook'unun 8 blok sınırı Bir Stop hook'u peş peşe sekiz kez engellerse Claude Code onu geçersiz kılar. Script'in bunu kendi kontrol etmeli: girdideki stop_hook_active alanı true ise erken çık. Gerçekten daha fazla tur gerekiyorsa sınırı CLAUDE_CODE_STOP_HOOK_BLOCK_CAP ile yükselt.

11 İzin modları ve güvenlik

PreToolUse hook'ları izin sorusundan önce çalışır — EndConversation dışındaki her tool için. dontAsk modunda bir çağrının onaylanmasının yollarından biri de budur: bu modda Claude yalnızca permissions.allow kurallarına uyan işleri, salt okunur Bash komutlarını ve bir PreToolUse hook'unun onayladığı çağrıları çalıştırır. Exit 2 ile engelleyen bir hook ise çağrıyı izin kuralları değerlendirilmeden önce durdurur; bu yüzden engelleme, eşleşen bir allow kuralı olsa bile geçerlidir. İzin kurallarının kendi sırası ve hangi ayar dosyasının kimi ezdiği settings.json: deny her zaman kazanır sayfasında.

Asimetrik kural Hook'lar kısıtlamayı sıkabilir ama gevşetemez. allow dönmek, settings'teki deny kurallarını baypas etmez; kurumunun ask'e ayarladığı connector tool'larının veya requiresUserInteraction işaretli MCP tool'larının sorusunu da bastıramaz.

Bu asimetri, hook'ları organizasyon politikası için doğru katman yapar: bir hook'un allow dönmesi, managed settings'te tanımlı deny kurallarını da geçersiz kılmaz. Kurum genelinde geçerli olması gerekiyorsa doğru yer managed policy settings'tir — oradaki hook'lar kullanıcı ayarlarındaki disableAllHooks ile kapatılamaz.

Hook, senin yetkinle çalışan koddur Bir hook, makinende senin kimliğinle çalışan keyfi bir shell komutudur ve .claude/settings.json bir repoya commit edilebilir. Denetlemediğin bir depoyu klonlayıp içinde çalışmaya başlamadan önce hook yapılandırmasına bak. /hooks menüsü tam olarak bunun için var: hangi komutun hangi event'te çalışacağını kaynak dosyasıyla birlikte gösterir.

Kurumsal tarafta üç denetim mevcut: allowManagedHooksOnly (kullanıcı, proje ve plugin hook'larını tamamen kapatır), allowedHttpHookUrls (HTTP hook endpoint'lerini allowlist'e bağlar) ve httpHookAllowedEnvVars (header'lara hangi ortam değişkenlerinin enjekte edilebileceğini sınırlar). Managed policy hook'ları kullanıcı ayarlarıyla devre dışı bırakılamaz.

Skill ve agent frontmatter hook'ları Proje seviyesindeki bir skill veya subagent'ın frontmatter hook'larının çalışması için o klasöre workspace trust onayı vermiş olman gerekir. Onay yoksa bileşen yine çalışır ama hook'ları sessizce atlanır — guardrail sandığın şey devrede olmayabilir.

12 Hata ayıklama ve tuzaklar

Hook hiç çalışmıyor

  • /hooks ile doğru event altında görünüyor mu bak.
  • Matcher tool adıyla birebir eşleşiyor mu — büyük/küçük harfe duyarlı.
  • Doğru event mi? PreToolUse öncesinde, PostToolUse sonrasında ateşlenir.
  • if alanını tool dışı bir event'e koymadın mı? Koyduysan hook hiç çalışmaz.

/hooks boş görünüyor

  • JSON geçerli mi — sondaki virgül ve yorum satırı kabul edilmez.
  • Dosya doğru yerde mi: proje için .claude/settings.json, global için ~/.claude/settings.json.
  • Birkaç saniyede görünmediyse file watcher değişikliği kaçırmış olabilir; oturumu yeniden başlat.

"hook error" görüyorum

Script'i elle test et — hook'un aldığı girdiyi taklit et:

echo '{"tool_name":"Bash","tool_input":{"command":"ls"}}' | ./my-hook.sh
echo $?  # exit kodunu gör
  • command not found: mutlak yol ya da ${CLAUDE_PROJECT_DIR} kullan.
  • jq: command not found: jq kur, ya da JSON'ı Python/Node ile ayrıştır.
  • Script hiç çalışmıyor: chmod +x ./my-hook.sh.
En sinsi hata: shell profili JSON'ı bozuyor Shell form'daki bir hook sh -c (Windows'ta Git Bash) ile çalışır. Profilinde koşulsuz bir echo varsa çıktısı hook'unun JSON'ının önüne eklenir ve ayrıştırma başarısız olur. Çözüm: profildeki echo'ları interaktif shell koşuluna al — if [[ $- == *i* ]]; then … fi — ya da "args": [] ile exec form'a geç.

Debug teknikleri

  • Ctrl+O ile transkript görünümü: her hook için tek satırlık özet. Başarı sessizdir; engelleyici hatalar stderr'i, engellemeyenler hata notunu gösterir.
  • Tam ayrıntı için debug log: claude --debug-file /tmp/claude.log ile başlat, başka bir terminalde tail -f /tmp/claude.log. Oturum ortasındaysan /debug ile aç.

Toparlarken

  • Exit 0 onay değildir — PreToolUse'da normal izin akışı sürer.
  • Exit 2 ve JSON birlikte kullanılmaz — 2 verdiğinde stdout yok sayılır.
  • Sessiz hook bilgi taşımaz — Claude'un bilmesi gerekeni açıkça döndür.
  • Hook'lar paralel çalışır — birinin engellemesi diğerinin yan etkisini iptal etmez, updatedInput'ta ise sıra belirsizdir.
  • PostToolUse geri alamaz — tool zaten çalıştı. Engelleme PreToolUse'un işidir.
  • Matcher büyük/küçük harfe duyarlı ve eşleşmeyen hook sessizce hiç çalışmaz.
  • Otomatik onayda matcher'ı dar tut — geniş bir PermissionRequest hook'u tüm güvenlik ağını kaldırır.
