01 Panoya kopyalıyorsan, orada bir server var

MCP (Model Context Protocol), Claude Code'u dış sistemlere bağlayan açık kaynaklı bir standart. Bir MCP server bağladığında Claude o sistemin verisini senin yapıştırdığın kadarıyla değil, doğrudan okuyup üzerinde işlem yaparak kullanır.

Karar kuralı basit: başka bir aracın ekranından sohbete veri taşıyorsan — issue tracker, monitoring dashboard, veritabanı, tasarım dosyası — o araç için bir MCP server aramaya değer. Tipik kullanımlar:

  • Issue'dan koda: "ENG-4521'de anlatılan özelliği yaz ve GitHub'da PR aç."
  • Üretim hatası: "Son 24 saatte en sık görülen hatalar neler?"
  • Veritabanı: "orders tablosunun şemasını göster."
  • Olaya tepki: bir MCP server aynı zamanda channel olarak da davranıp oturuma mesaj itebilir; böylece sen başındayken değilken bile Claude gelen olaya tepki verir.

Bağlanacak sunucuyu Anthropic Directory'de arayabilirsin; oradaki bağlantılar Claude Code ile aynı altyapıyı kullandığı için hepsi claude mcp add ile eklenir. Kendin yazacaksan resmi mcp-server-dev plugin'i iskeleti kurar:

/plugin install mcp-server-dev@claude-plugins-official
/mcp-server-dev:build-mcp-server
Önce güven, sonra bağla Bir MCP server, Claude'un context'ine dışarıdan içerik taşır. Dış içerik getiren her sunucu prompt injection yüzeyidir: bir issue açıklamasının içine gömülü talimat, Claude'a yönelik bir komut gibi davranabilir. Kaynağına güvenmediğin sunucuyu bağlama; bağladıklarına da 08. bölümdeki izin kurallarıyla sınır çiz.

02 Hangi transport? Neredeyse her zaman http

Sunucu ya makinende bir süreç olarak çalışır (stdio) ya da uzakta bir uç noktadır (http, sse, ws). Seçim çoğu zaman senin değil, sunucunun kararıdır — dokümantasyonunda hangi adres veriliyorsa onu kullanırsın.

TransportNe zamanNasıl eklenirNot
http Bulut tabanlı servisler. Uzak sunucular için önerilen seçenek. --transport http OAuth destekler. JSON içinde type alanı streamable-http takma adını da kabul eder.
stdio Yerel süreç: sistem erişimi gereken araçlar, kendi yazdığın script'ler. --transport stdio -- <komut> Kopan bağlantı otomatik yeniden kurulmaz (07. bölüm).
sse Yalnızca SSE uç noktası sunan servisler. --transport sse Deprecated. Mümkünse http kullan.
ws Claude'a habersiz olay iten sunucular; kalıcı çift yönlü bağlantı. Sadece claude mcp add-json veya .mcp.json --transport bayrağı ws kabul etmez, OAuth desteklemez — kimlik doğrulama yalnızca header ile. 
# Uzak HTTP sunucusu
claude mcp add --transport http notion https://mcp.notion.com/mcp

# Bearer token ile
claude mcp add --transport http secure-api https://api.example.com/mcp \
  --header "Authorization: Bearer your-token"

# WebSocket: yalnızca JSON ile
claude mcp add-json events-server \
  '{"type":"ws","url":"wss://mcp.example.com/socket","headers":{"Authorization":"Bearer YOUR_TOKEN"}}'
Sessiz atlanan sunucu JSON içinde url yazıp type yazmamak bir yapılandırma hatasıdır: Claude Code type'ı olmayan girdiyi stdio sunucusu sanar. O sunucuyu atlar ve MCP server "<ad>" has a "url" but no "type" uyarısını basar. v2.1.202 öncesinde bu durum command: expected string, received undefined olarak raporlanıyordu.

03 İlk sunucu: tek satır, bir de -- kuralı

Uzak sunucu için ad ve URL yeter. Yerel bir sunucu içinse komut satırının nerede bittiğini Claude Code'a söylemen gerekir:

# Genel sözdizimi
claude mcp add [options] <name> -- <command> [args...]

# Gerçek örnek: Airtable
claude mcp add --env AIRTABLE_API_KEY=YOUR_KEY --transport stdio airtable \
  -- npx -y airtable-mcp-server

# Gerçek örnek: PostgreSQL — salt okunur kullanıcıyla
claude mcp add --transport stdio db -- npx -y @bytebase/dbhub \
  --dsn "postgresql://readonly:pass@prod.db.com:5432/analytics"
İki tire ne işe yarıyor --, Claude'un kendi seçeneklerini (--transport, --env, --scope) sunucuyu çalıştıran komuttan ayırır. Sonrasındaki her şey sunucuya olduğu gibi geçer. Onu yazmazsan Claude Code, sunucunun --port gibi bayraklarını kendi seçeneği sanıp hata verir.

İki küçük tuzak daha:

  • --env ile sunucu adı yan yana gelmesin. --env birden çok KEY=value kabul ettiği için, hemen ardından gelen sunucu adını da bir çift sanır ve reddeder. Yukarıdaki örneklerde olduğu gibi aralarına en az bir başka seçenek koy.
  • Ad kısıtı: claude mcp komutlarıyla eklenen sunucu adları yalnızca harf, rakam, tire ve alt çizgi içerebilir.
  • Rezerve adlar: workspace, claude-in-chrome, computer-use, Claude Preview ve Claude Browser yerleşik sunuculara ait. claude mcp add bu adları hatayla reddeder; yapılandırma dosyasına elle yazılmışsa sunucu yükleme sırasında atlanır.

Elinde hazır JSON varsa

claude mcp add-json weather-api '{"type":"http","url":"https://api.weather.com/mcp","headers":{"Authorization":"Bearer token"}}'

# Claude Desktop'taki sunucuları içe aktar (macOS ve WSL)
claude mcp add-from-claude-desktop

# Claude Code'un kendisini bir MCP server olarak çalıştır
claude mcp serve

claude mcp serve başlarken hiçbir şey yazdırmaz. Bir stdio sunucusu stdin/stdout üzerinden konuştuğu için sessiz ve bloklanmış bir terminal, sunucunun çalıştığı ve istemci beklediği anlamına gelir.

04 local, project, user: sunucu nerede yaşasın?

-s / --scope bayrağı sunucunun hangi projelerde yükleneceğini ve ekiple paylaşılıp paylaşılmayacağını belirler. Varsayılan local'dır.

ScopeYüklendiği yerEkiple paylaşılır mıNerede saklanır
local (varsayılan)Yalnızca eklediğin projeHayır~/.claude.json, o projenin yolu altında
projectYalnızca o projeEvet, sürüm kontrolü ileProje kökünde .mcp.json
userMakinendeki tüm projelerHayır~/.claude.json
 
# local (varsayılan): kişisel, deneysel, kimlik bilgisi taşıyan sunucular
claude mcp add --transport http stripe https://mcp.stripe.com

# user: her projede yanında olsun istediğin kişisel araçlar
claude mcp add --transport http hubspot --scope user https://mcp.hubspot.com/anthropic

# project: ekibin tamamının aynı araçlara sahip olması için
claude mcp add --transport http shared-server --scope project https://example.com/mcp
Adlar karışmasın MCP'deki "local scope" ile genel local settings aynı şey değil. MCP local sunucuları ~/.claude.json içinde (ev dizininde) durur; genel yerel ayarlar ise proje içindeki .claude/settings.local.json dosyasındadır.

Aynı sunucu iki yerde tanımlıysa

Claude Code sunucuya bir kez bağlanır ve en yüksek öncelikli kaynaktaki tanımı kullanır. Alanlar birleştirilmez — kazanan kaynağın girdisi olduğu gibi geçerlidir:

  • 1. Local scope
  • 2. Project scope
  • 3. User scope
  • 4. Plugin'lerin sağladığı sunucular
  • 5. claude.ai connector'ları

Üç scope birbirini ada göre eşler. Plugin'ler ve connector'lar ise uç noktaya göre eşleşir: yukarıdaki bir sunucuyla aynı URL'i ya da aynı komutu gösteren bir plugin sunucusu kopya sayılır. Kendi eklediğin bir sunucu aynı URL'li bir claude.ai connector'ını gölgelediğinde /mcp connector'ı "hidden" olarak listeler ve kopyayı nasıl kaldıracağını gösterir.

05 .mcp.json'ı commit'lemek: ekibin tamamı aynı araçlarla

--scope project ile eklediğin sunucu proje kökündeki .mcp.json dosyasına yazılır. Bu dosyayı sürüm kontrolüne al: ekibe katılan herkes aynı MCP araçlarıyla başlar.

{
  "mcpServers": {
    "shared-server": {
      "type": "http",
      "url": "https://example.com/mcp"
    }
  }
}

Sırları dosyaya yazma: değişken genişletme

Makineye özgü yollar ve API anahtarları için .mcp.json ortam değişkeni genişletmesini destekler: ${VAR} ve varsayılanlı hâli ${VAR:-default}. Genişletme command, args, env, url ve headers alanlarında çalışır.

{
  "mcpServers": {
    "api-server": {
      "type": "http",
      "url": "${API_BASE_URL:-https://api.example.com}/mcp",
      "headers": {
        "Authorization": "Bearer ${API_KEY}"
      }
    }
  }
}

Bir değişken tanımlı değilse ve varsayılanı da yoksa yapılandırma yine yüklenir: Claude Code claude mcp list çıktısında o sunucu için eksik değişken uyarısı basar ve ${VAR} metnini genişletmeden olduğu gibi kullanır. Yani bağlantı hatası beklediğin yerde sessiz bir yanlış değer görürsün — uyarı satırını okumayı alışkanlık edin.

Onay akışı: proje sunucuları kendiliğinden çalışmaz

Güvenlik gerekçesiyle Claude Code, .mcp.json'daki proje sunucularını kullanmadan önce etkileşimli oturumda onay ister. Verdiğin kararları sıfırlamak için:

claude mcp reset-project-choices

Onayı ayarlardan da yönetebilirsin:

AyarEtkisi
enableAllProjectMcpServers.mcp.json'daki tüm sunucuları otomatik onaylar.
enabledMcpjsonServersYalnızca adını saydığın sunucuları onaylar: ["memory", "github"]
disabledMcpjsonServersAdını saydığın sunucuları reddeder — her modda geçerlidir.
Klonlanan repo kendi sunucusunu onaylayamaz v2.1.196'dan itibaren claude mcp list ve claude mcp get, workspace'e güvenene kadar .mcp.json onaylarını yalnızca repoya commit'lenmemiş ayar dosyalarından okur. Projenin .claude/settings.json'ına yazılmış enableAllProjectMcpServers güvenilmeyen bir klasörde yok sayılır; sunucu ⏸ Pending approval olarak bekler. Klasörde claude çalıştırıp güven onayını verdiğinde devreye girer. Kullanıcı ayarların (~/.claude/settings.json), managed ayarlar ve --settings ile geçilenler bu durumdan etkilenmez.
Etkileşimsiz çalıştırmada onay ekranı yoktur claude -p koşuları, Agent SDK oturumları ve bulut oturumları o soruyu soramaz: proje sunucularını sormadan yükler. Bir sunucuyu oralarda da dışarıda tutmak istiyorsan disabledMcpjsonServers'a ekle ya da proje ayarlarını tümden devre dışı bırak (--setting-sources, SDK'da settingSources).

06 OAuth'lu sunucular ve /mcp ekranı

Bulut sunucularının çoğu kimlik doğrulaması ister ve Claude Code bunun için OAuth 2.0 destekler. Sunucuyu eklerken kimlik bilgisi vermezsin; girişi sonradan yaparsın:

claude mcp add --transport http sentry https://mcp.sentry.dev/mcp
/mcp

Tarayıcıda giriş adımlarını tamamladığında sunucu /mcp menüsünde connected görünür. v2.1.186'dan itibaren aynı akışı oturum açmadan, doğrudan kabuktan da çalıştırabilirsin:

claude mcp login sentry
claude mcp logout sentry

# SSH oturumu veya ekran sunucusuz Linux: URL'i bas, geri dönüş adresini yapıştır
claude mcp login sentry --no-browser

Komut yerel tarayıcı olmadığını kendi de algılar ve yetkilendirme URL'ini basar; yapıştırma adımı için etkileşimli terminal gerektiğinden ssh -t ile bağlan.

Sunucu dinamik kayıt desteklemiyorsa

"Incompatible auth server: does not support dynamic client registration" hatasını görüyorsan sunucunun geliştirici portalından bir OAuth uygulaması kaydetmen gerekir. Kayıt sırasında istenen redirect URI http://localhost:PORT/callback biçimindedir; aynı portu --callback-port ile ver:

claude mcp add --transport http \
  --client-id your-client-id --client-secret --callback-port 8080 \
  my-server https://mcp.example.com/mcp

# CI'da etkileşimli soruyu atlamak için
MCP_CLIENT_SECRET=your-secret claude mcp add --transport http \
  --client-id your-client-id --client-secret --callback-port 8080 \
  my-server https://mcp.example.com/mcp
  • --client-secret değeri komut satırında almaz; maskeli girdi olarak sorar.
  • Sır yapılandırmaya değil, sistem anahtarlığına (macOS) veya bir kimlik dosyasına yazılır.
  • --callback-port tek başına da kullanılabilir — dinamik kayıtla birlikte portu sabitler.
  • Bu bayraklar yalnızca HTTP ve SSE için anlamlıdır; stdio sunucularında etkisizdir.
  • Erişimi geri almak için /mcp menüsündeki "Clear authentication".

Kapsamı daraltmak: oauth.scopes

Yetkilendirme sunucusu senin vermek istediğinden fazla scope reklam ediyorsa, istenen kümeyi .mcp.json içinde sabitle. Değer, RFC 6749'daki gibi boşlukla ayrılmış tek bir metindir ve hem authServerMetadataUrl'yi hem de sunucunun keşfettiği scope'ları ezer:

{
  "mcpServers": {
    "slack": {
      "type": "http",
      "url": "https://mcp.slack.com/mcp",
      "oauth": {
        "scopes": "channels:read chat:write search:read"
      }
    }
  }
}

Sunucu bir tool çağrısına 403 insufficient_scope dönerse Claude Code aynı sabit scope'larla yeniden yetkilendirir — yani ihtiyacın olan tool sabit kümenin dışındaysa listeyi sen genişletmelisin.

OAuth değil, kurum içi kimlik doğrulama

Kerberos, kısa ömürlü token veya iç SSO kullanıyorsan headersHelper ile bağlantı anında header üretebilirsin:

{
  "mcpServers": {
    "internal-api": {
      "type": "http",
      "url": "https://mcp.internal.example.com",
      "headersHelper": "/opt/bin/get-mcp-auth-headers.sh"
    }
  }
}
  • Komut stdout'a string'lerden oluşan bir JSON nesnesi yazmalı.
  • Kabukta, oturumun çalışma dizininde ve 10 saniyelik zaman aşımıyla koşar — mutlak yol kullan.
  • Her bağlantıda yeniden çalışır, önbellek yoktur; token'ı tekrar kullanmak script'inin işidir.
  • Dinamik header'lar aynı adlı statik headers değerlerini ezer.
  • v2.1.193'ten itibaren bir tool çağrısı 401/403 dönerse helper yeniden koşturulur, bağlantı tazelenir ve çağrı bir kez tekrarlanır.
  • headersHelper keyfi kabuk komutu çalıştırır: project veya local scope'ta tanımlıysa yalnızca workspace güven onayını verdikten sonra koşar.
Header koyduysan OAuth'a düşmez Sunucu için headers.Authorization tanımladıysan ve sunucu bu header'ı reddederse Claude Code bağlantıyı başarısız sayar; OAuth akışına geri dönmez. Token'ın o MCP uç noktası için geçerli olduğundan emin ol ya da header'ı kaldırıp OAuth'u kullan.

Birkaç ayrıntı hata avında zaman kazandırır:

  • Kopyala-yapıştır boşluğu: Claude Code command, url, her args girdisi ile env ve headers altındaki değer ve anahtar adlarında gizli baştaki/sondaki boşluğu uyarır — örneğin Leading or trailing whitespace in: headers.Authorization. Değeri kırpmaz, yazıldığı gibi kullanır; düzeltmek sana kalmış.
  • Yeniden bağlanma: HTTP/SSE sunucusu oturum ortasında koparsa üstel geri çekilmeyle beş deneme yapılır (1 saniyeden başlayıp katlanarak). Beşi de başarısız olursa sunucu failed işaretlenir, /mcp'den elle yeniden denersin. Stdio sunucuları yerel süreç olduğu için otomatik yeniden bağlanmaz.
  • WebSocket sunucuları claude mcp list çıktısında görünmez. claude mcp get <ad> ya da /mcp paneline bak.
  • Aynı ad, aynı scope: claude mcp add'i tekrar çalıştırmak MCP server sentry already exists in local config hatasıyla biter.

08 mcp__server__tool: kuralların dayandığı ad

Bir MCP tool'unun çağrılabilir adı mcp__<server>__<tool> biçimindedir. Bu ad yalnızca ekranda görünen bir etiket değil; izin kuralları, hook matcher'ları ve subagent'ların tools listesi bu ada göre eşleşir. Kuralların değerlendirilme sırası ve hangi ayar dosyasına yazılacağı settings.json: deny her zaman kazanır sayfasında.

KuralNe eşler
mcp__puppeteerpuppeteer sunucusunun sağladığı her tool
mcp__puppeteer__*Aynısı, joker sözdizimiyle
mcp__puppeteer__puppeteer_navigateYalnızca o tek tool
mcp__github__get_*github sunucusunun get_ ile başlayan tool'ları
 
{
  "permissions": {
    "allow": ["mcp__sentry__*", "mcp__github__get_*"],
    "deny": ["mcp__*"]
  }
}
allow kurallarında sunucu adı sabit olmalı Allow kuralları joker'i yalnızca düz yazılmış bir mcp__<server>__ önekinden sonra kabul eder; sunucu bölümü joker içeremez. "*", "B*" veya "mcp__*" gibi bir allow kuralı uyarıyla atlanır ve hiçbir şeyi otomatik onaylamaz. Aynı desen deny tarafında sorunsuz çalışır — bütün MCP tool'larını kapatmanın yolu budur.

İki ayrıntı sık şaşırtır:

  • Plugin'in getirdiği sunucular farklı adlanır. Tam biçim mcp__plugin_<plugin-adı>_<server-adı>__<tool>'dur; örneğin mcp__plugin_my-plugin_database-tools__query. Çıplak sunucu adına yazılmış bir hook matcher'ı (mcp__database-tools__.*) plugin sunucusunda hiç tetiklenmez. Sunucunun kendisi ise plugin:<plugin-adı>:<server-adı> adıyla kaydolur.
  • claude.ai connector tool'ları mcp__claude_ai_<server>__<tool> olarak görünür. Kurumun bir connector tool'unu ask'e ayarladıysa allow kuralların işe yaramaz: Claude Code auto ve bypassPermissions modlarında bile her çağrıda sorar, dontAsk modunda ise çağrıyı reddeder.
Sunucu yazarları için Bir tool'u tools/list yanıtında _meta["anthropic/requiresUserInteraction"]: true ile işaretlersen Claude Code o tool için her çağrıda izin sorar; "bir daha sorma" seçeneği sunmaz ve eşleşen allow kuralları soruyu atlatmaz. Onayın kendisi işin amacı olan adımlar için — erişim talebi, rıza ekranı — doğru araç budur. (v2.1.199+)

09 Context faturasını kim ödüyor?

Eskiden "çok fazla MCP server context'i şişirir" doğru bir uyarıydı. Bugün varsayılan davranış tool search: oturum başında yalnızca tool adları ve sunucu talimatları yüklenir, şemalar Claude ihtiyaç duyana kadar ertelenir. Claude Code sunucu başına sabit bir tool sınırı koymaz; pratik sınır context bütçendir.

ENABLE_TOOL_SEARCHDavranış
(ayarsız)Varsayılan. Tüm MCP tool'ları ertelenir, ihtiyaç oldukça yüklenir.
trueErteleme zorlanır; beta başlığı proxy'lere de gönderilir.
autoEşik modu: şemalar context'in %10'una sığıyorsa baştan yüklenir, taşan kısım ertelenir.
auto:NEşik yüzdesini sen ver — auto:5 gibi.
falseTüm MCP tool'ları baştan yüklenir, erteleme yok.

Tool search tool_reference bloklarını destekleyen bir model ister: Claude Sonnet 4.5, Haiku 4.5, Opus 4.5 ve sonrası. ANTHROPIC_BASE_URL birinci taraf olmayan bir adrese bakıyorsa Claude Code bunu kendiliğinden kapatır — çoğu proxy o blokları iletmez.

Her turda lazım olan sunucuyu muaf tut

Bir sunucunun tool'ları arama adımı olmadan hep görünür olsun istiyorsan alwaysLoad kullan. Bunun bedeli var: baştan yüklenen her tool, konuşmaya kalacak context'ten yer alır. Ayrıca alwaysLoad: true açılışın o sunucunun tool'larını beklemesine yol açar (5 saniyelik bağlantı zaman aşımıyla sınırlı) — diğer sunucular varsayılan olarak arka planda bağlanır.

{
  "mcpServers": {
    "core-tools": {
      "type": "http",
      "url": "https://mcp.example.com/mcp",
      "alwaysLoad": true
    }
  }
}

Asıl fatura: tool çıktıları

Şemalar ertelense de tool'un döndürdüğü sonuç context'e girer. Claude Code bunu iki eşikle sınırlar:

  • 10.000 token üzerindeki her MCP tool çıktısı için uyarı gösterir. Bu eşik sabittir.
  • Varsayılan üst sınır 25.000 token'dır; MAX_MCP_OUTPUT_TOKENS ile yükseltilir (export MAX_MCP_OUTPUT_TOKENS=50000).
  • Sunucu yazıyorsan tek bir tool'un sınırını _meta["anthropic/maxResultSizeChars"] ile yükseltebilirsin — üst tavan 500.000 karakter. Bu ek açıklama metin içerik için ortam değişkeninden bağımsız çalışır, ama görsel döndüren tool'lar yine MAX_MCP_OUTPUT_TOKENS'a tabidir.
Nereye bakılır Sunucu başına maliyeti /mcp gösterir; genel kırılım için /usage, anlık bağlam dağılımı için /context. Bir işi hem CLI hem MCP ile yapabiliyorsan CLI genelde daha ucuzdur: gh, aws, sentry-cli hiçbir tool listesi eklemez.

10 Kapat ama silme

Bir sunucuyu bu hafta kullanmıyorsan yapılandırmasını silmene gerek yok: /mcp panelinden kapat. Sunucu listede disabled olarak durur, Claude Code ona bağlanmaz.

Tercihin proje bazında ~/.claude.json içine yazılır ve ayrık iki listeden birine düşer:

ListeKimi kapsarAnlamı
disabledMcpServersKullanıcı sunucuları, plugin sunucuları, claude.ai connector'ları ve varsayılan olarak açık yerleşik sunucularOpt-out: buradakine bağlanılmaz
enabledMcpServersVarsayılan olarak kapalı yerleşik sunucular (computer-use gibi)Opt-in: yalnızca buradakine bağlanılır

Claude Code her sunucu için bu listelerden yalnızca birine bakar; biri diğerini ezmez. Normal bir sunucuyu enabledMcpServers'a yazarsan o girdi yok sayılır. Bu ikisinin, .mcp.json onaylarını yöneten enabledMcpjsonServers / disabledMcpjsonServers ile hiçbir ilgisi yoktur — adları benzer, işleri ayrı.

11 @ ile resource, / ile prompt

MCP sunucuları yalnızca tool sunmaz. İki yüzeyi daha var ve ikisi de tanıdık sözdizimini kullanır.

Resources: dosya gibi @ ile referans ver

İstemin içinde @ yazdığında bağlı sunucuların kaynakları da dosyaların yanında otomatik tamamlamada çıkar. Biçim: @server:protocol://resource/path

@github:issue://123 sorununu inceleyip bir düzeltme önerir misin?

@postgres:schema://users ile @docs:file://database/user-model arasındaki farkı karşılaştır

Referans verilen kaynak otomatik olarak getirilip eke dönüştürülür; yollar bulanık aramayla (fuzzy) taranabilir.

Prompts: sunucudan gelen slash command'lar

Sunucunun tanımladığı prompt'lar / menüsünde /mcp__servername__promptname biçiminde görünür. Argümanları boşlukla ayırarak verirsin:

/mcp__github__list_prs
/mcp__github__pr_review 456
/mcp__jira__create_issue "Bug in login flow" high

Sunucu ve prompt adları normalleştirilir — boşluklar alt çizgiye dönüşür. Prompt'un sonucu doğrudan konuşmaya enjekte edilir.

Elicitation: sunucu sana soru sorduğunda

Bir sunucu iş ortasında kendi başına elde edemeyeceği bir bilgiye ihtiyaç duyarsa Claude Code etkileşimli bir kutucuk açar: form modunda sunucunun tanımladığı alanları doldurursun, URL modunda tarayıcıda akışı tamamlayıp CLI'da onaylarsın. Senin tarafında yapılandırma gerekmez. Diyaloğu göstermeden otomatik cevap vermek istersen Elicitation hook'unu kullan.

12 Hızlı referans

  • Ekle (uzak): claude mcp add --transport http <ad> <url>
  • Ekle (yerel): claude mcp add --transport stdio <ad> -- <komut> [args]
  • Kısa bayraklar: -t = --transport, -H = --header, -s = --scope, -e = --env
  • Scope: local (varsayılan, ~/.claude.json) · project (.mcp.json, ekiple paylaşılır) · user (tüm projeler)
  • Öncelik: local → project → user → plugin → claude.ai connector; alanlar birleştirilmez
  • Yönet: claude mcp list · get <ad> · remove <ad> · add-json · reset-project-choices
  • Giriş: /mcp · claude mcp login <ad> · logout · --no-browser
  • İzin kuralı: mcp__<server>__<tool>; allow'da joker yalnızca sunucu adından sonra
  • Plugin tool adı: mcp__plugin_<plugin>_<server>__<tool>
  • Context: tool search varsayılan açık · ENABLE_TOOL_SEARCH · sunucu bazında alwaysLoad
  • Çıktı sınırı: 10.000 token'da uyarı (sabit), 25.000 token varsayılan tavan, MAX_MCP_OUTPUT_TOKENS ile yükselir
  • Zaman aşımı: MCP_TIMEOUT (başlatma) · sunucu bazında timeout · MCP_TOOL_TIMEOUT · CLAUDE_CODE_MCP_TOOL_IDLE_TIMEOUT
  • Kapat: /mcp toggle → disabledMcpServers; .mcp.json onayı → disabledMcpjsonServers
  • Resource: @server:protocol://path · Prompt: /mcp__server__prompt
