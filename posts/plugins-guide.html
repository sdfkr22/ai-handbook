01 Skill'in .claude/'da kaldığı sürece senindir

Claude Code'a özel yetenek eklemenin iki yolu var ve ikisi de aynı dosyaları kullanır. Fark, dosyaların kime ulaştığında.

.claude/skills/, .claude/agents/, .claude/settings.json — bunlar hızlı ve yeterlidir; ta ki "bunu ekipteki herkes kullansın" diyene kadar. O noktada ya herkese tek tek dosya kopyalatırsın, ya da paketlersin. Plugin tam olarak bu paketleme biçimi: skill'ler, subagent'lar, hook'lar, MCP server'lar ve LSP server'lar tek bir klasörde, tek bir kurulum komutuyla.

YaklaşımSkill adıNe için iyi
Standalone
.claude/ klasörü		 /hello Kişisel akışlar, projeye özgü düzenlemeler, hızlı deneme
Plugin
kendi kendine yeten klasör + .claude-plugin/plugin.json		 /plugin-adi:hello Ekiple paylaşma, topluluğa dağıtma, sürümlü yayın, projeler arası tekrar kullanım

Plugin'in tek başına getirdiği şeyler:

  • Tek kurulum, çok bileşen. Bir skill'i, onu tetikleyen hook'u ve ihtiyaç duyduğu MCP server'ı ayrı ayrı değil, birlikte kurarsın.
  • Namespace. Plugin skill'leri her zaman /plugin-adi:skill-adi biçiminde görünür; iki plugin aynı adlı skill'i taşısa bile çakışmaz.
  • Sürüm ve güncelleme. Marketplace üzerinden dağıtılan plugin'ler arka planda güncellenebilir.
  • Kapatılabilirlik. /plugin disable ile tüm paket bir anda devre dışı kalır; dosya silmeye gerek yok.
Sıralama Doğru akış: önce .claude/ altında hızlıca yaz ve çalıştığını gör, sonra paylaşmaya karar verdiğinde plugin'e taşı. Bileşen dosyaları aynı olduğu için taşıma çoğunlukla cp -r işidir.

02 Beş dakikada ilk plugin

Bir plugin en sade halinde iki dosyadır: manifest ve bir skill.

# 1. Klasörler
mkdir my-first-plugin
mkdir my-first-plugin/.claude-plugin
mkdir -p my-first-plugin/skills/hello

my-first-plugin/.claude-plugin/plugin.json:

{
  "name": "my-first-plugin",
  "description": "A greeting plugin to learn the basics",
  "version": "1.0.0",
  "author": { "name": "Your Name" }
}

my-first-plugin/skills/hello/SKILL.md:

---
description: Greet the user with a personalized message
---

Greet the user named "$ARGUMENTS" warmly and ask how you can help them today.

Kurulum yok, marketplace yok — doğrudan yükleyip dene:

claude --plugin-dir ./my-first-plugin

Oturum açıldığında skill'in adı plugin adıyla önekli olur:

/my-first-plugin:hello Alex

Daha da kısa yol: claude plugin init

Her açılışta --plugin-dir yazmak istemiyorsan, plugin'i doğrudan skills klasöründe geliştir:

claude plugin init my-tool
claude plugin init my-tool --with skills hooks mcp

Bu komut ~/.claude/skills/my-tool/ altında bir .claude-plugin/plugin.json ve başlangıç SKILL.md dosyası oluşturur. Bir sonraki oturumda plugin my-tool@skills-dir adıyla kendiliğinden yüklenir — ne marketplace ne de kurulum adımı gerekir. --with değerleri: skills, agents, hooks, mcp, lsp, output-style, channel.

Skills-dir plugin'lerinin sınırı ~/.claude/skills/ altındaki plugin her projede yüklenir. Projenin .claude/skills/ klasöründeki bir plugin ise yalnızca workspace'e güven verdikten sonra yüklenir; MCP server'ları ayrıca onay ister, LSP server'ları güven sonrası başlar ve background monitor'ları hiç yüklenmez. Ayrıca proje kapsamındaki bu plugin'ler repo köküne kadar yukarı taranmaz — Claude Code'u repo kökünden başlatman gerekir.

03 Neyi nereye koyacaksın?

Plugin'lerde en sık yapılan hata tek bir cümleyle özetlenebilir: .claude-plugin/ klasörüne yalnızca plugin.json girer. Diğer her şey plugin kökünde durur.

En sık hata commands/, agents/, skills/ veya hooks/ klasörlerini .claude-plugin/ içine koyarsan plugin yüklenir ama bileşenlerin görünmez. Semptom tam olarak budur: "plugin listede var, skill'i yok."

Tek skill'lik plugin Plugin'in yalnızca bir skill taşıyacaksa skills/ klasörü açmadan SKILL.md'yi doğrudan plugin köküne koyabilirsin. Bu durumda frontmatter'daki name alanını mutlaka yaz — yoksa skill adı kurulum klasörünün adından türetilir ve bu ad marketplace kurulumlarında her güncellemede değişen bir sürüm dizesidir.
CLAUDE.md burada işlemez Plugin kökündeki bir CLAUDE.md proje context'i olarak yüklenmez. Plugin, context'e katkısını skill'ler, agent'lar ve hook'lar üzerinden yapar. Talimat göndermek istiyorsan onu bir skill'in içine koy.

04 plugin.json'da tek zorunlu alan var

Şaşırtıcı olabilir: manifest dosyasının kendisi opsiyoneldir. Yoksa Claude Code bileşenleri varsayılan konumlardan keşfeder ve plugin adını klasör adından türetir. Manifest yazdığın anda ise zorunlu tek alan name'dir.

{
  "$schema": "https://json.schemastore.org/claude-code-plugin-manifest.json",
  "name": "plugin-name",
  "displayName": "Plugin Name",
  "version": "1.2.0",
  "description": "Brief plugin description",
  "author": {
    "name": "Author Name",
    "email": "author@example.com",
    "url": "https://github.com/author"
  },
  "homepage": "https://docs.example.com/plugin",
  "repository": "https://github.com/author/plugin",
  "license": "MIT",
  "keywords": ["deployment", "ci-cd"],
  "skills": "./custom/skills/",
  "agents": ["./custom/agents/reviewer.md"],
  "hooks": "./config/hooks.json",
  "mcpServers": "./mcp-config.json",
  "lspServers": "./.lsp.json",
  "experimental": { "themes": "./themes/", "monitors": "./monitors.json" },
  "dependencies": ["helper-lib", { "name": "secrets-vault", "version": "~2.1.0" }]
}

Tanınmayan alanlar sorun çıkarmaz

Claude Code tanımadığı üst düzey alanları yok sayar. Böylece aynı plugin.json'ı başka bir ekosistemin manifest'i olarak da tutabilirsin. claude plugin validate bunları hata değil uyarı olarak raporlar; bir alan tanınan bir addan bir-iki karakter farklıysa doğru adı da önerir. CI'da yazım hatalarını yakalamak için --strict ile uyarıları hataya çevir.

userConfig: kullanıcıya settings.json düzenlettirme

{
  "userConfig": {
    "api_endpoint": {
      "type": "string",
      "title": "API endpoint",
      "description": "Your team's API endpoint"
    },
    "api_token": {
      "type": "string",
      "title": "API token",
      "description": "API authentication token",
      "sensitive": true
    }
  }
}

type değerleri: string, number, boolean, directory, file. Değerler MCP ve LSP yapılandırmalarında ve hook komutlarında ${user_config.KEY} ile kullanılır, hook süreçlerine ayrıca CLAUDE_PLUGIN_OPTION_<KEY> ortam değişkeni olarak geçer. sensitive: true olan değerler settings.json yerine güvenli depoya (macOS Keychain veya ~/.claude/.credentials.json) yazılır.

Shell'e giden alanlar reddeder Shell biçimindeki hook komutları, monitor komutları ve MCP headersHelper alanı ${user_config.*} ikamesini kabul etmez — çünkü değerin içeriği shell'de çalıştırılabilirdi. Hook'larda args ile exec form kullan veya ortam değişkenini oku; monitor script'lerinde değeri kendi config dosyandan okut.

05 Ad koymak, geri dönüşü zor bir karar

Plugin'in name değeri yalnızca bir etiket değil; kullanıcıların enabledPlugins ayarında, pluginConfigs kaydında ve /plugin install komutunda yazdıkları kimliktir. Değiştirdiğinde mevcut tüm kurulumlar kırılır.

  • kebab-case, boşluksuz. Küçük harf, rakam ve tire. Claude Code başka biçimleri de kabul eder ama claude plugin validate uyarı verir ve claude.ai marketplace senkronizasyonu reddeder.
  • ASCII ve kısa. Claude Desktop'ın yönetilen marketplace senkronizasyonu en fazla 128 karakter, yalnızca harf/rakam/./_/- kabul eder ve harf veya rakamla başlamalıdır. Uymayan bir plugin adı sessizce düşürülür.
  • Ad = namespace. plugin-dev adlı plugin'in agent-creator agent'ı arayüzde plugin-dev:agent-creator olarak görünür; skill'leri /plugin-dev:skill-adi ile çağrılır. Öneki değiştirmek istiyorsan plugin.json'daki name'i değiştirirsin.
  • Marketplace adı kazanır. Bir marketplace girdisi plugin'i farklı bir adla listeliyorsa, enabledPlugins anahtarlarında ve /plugin arayüzünde geçerli olan marketplace girdisindeki addır.
  • Görünen adı değiştirmek için displayName. Arayüzdeki etiketi güncellemek istiyorsan name'e dokunma, displayName ekle.

Adı gerçekten değiştirmen gerekirse: renames

Marketplace dosyasına üst düzey bir renames haritası ekle; mevcut kullanıcılar plugin-not-found hatası almak yerine otomatik göç eder.

{
  "name": "acme-tools",
  "owner": { "name": "Acme" },
  "plugins": [
    { "name": "code-formatter", "source": "./plugins/code-formatter" }
  ],
  "renames": {
    "formatter": "code-formatter",   // yeni ada yönlendir
    "legacy-linter": null          // tamamen kaldırıldı
  }
}

renames'i append-only bir tarih kaydı gibi düşün: eski girdileri silme, yeni yeniden adlandırmalarda zincire halka ekle. Claude Code zinciri takip eder. Düzenledikten sonra claude plugin validate . çalıştır — döngü oluşturan veya null'a ya da mevcut bir plugin adına ulaşmayan zincirleri reddeder.

Rezerve marketplace adları Marketplace'ine şu adları veremezsin: claude-code-marketplace, claude-code-plugins, claude-plugins-official, claude-plugins-community, claude-community, anthropic-marketplace, anthropic-plugins, agent-skills, anthropic-agent-skills ve benzerleri. Resmî kaynakları taklit eden adlar (official-claude-plugins gibi) da engellenir. Claude Code bu kontrolü her yüklemede tekrarlar.

06 Plugin'in içine ne sığar?

Bir plugin sadece slash command taşıyıcısı değil. Aşağıdakilerin hepsi aynı pakette yaşayabilir.

Skills

skills/<ad>/SKILL.md. Kurulumda otomatik keşfedilir, /plugin-adi:skill-adi ile çağrılır. Kurulum özeti Run /reload-plugins to activate. diyorsa o komutu çalıştır.

Agents

---
name: agent-name
description: What this agent specializes in and when Claude should invoke it
model: sonnet
effort: medium
maxTurns: 20
disallowedTools: Write, Edit
---

Detailed system prompt for the agent.

Desteklenen frontmatter alanları: name, description, model, effort, maxTurns, tools, disallowedTools, skills, memory, background, isolation (tek geçerli değer "worktree").

Plugin agent'larında yasak Güvenlik nedeniyle plugin'in getirdiği agent'larda hooks, mcpServers ve permissionMode alanları desteklenmez. Kendi .claude/agents/ dosyalarında çalışan bu alanları plugin'e taşırsan sessizce beklediğin gibi davranmaz.

Hooks

{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          { "type": "command", "command": "\"${CLAUDE_PLUGIN_ROOT}\"/scripts/format-code.sh" }
        ]
      }
    ]
  }
}

Plugin hook'ları kullanıcı hook'larıyla aynı olaylara tepki verir: SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, PostToolUseFailure, SubagentStart, SubagentStop, PreCompact, SessionEnd ve onlarca diğeri. Hook tipleri: command, http, mcp_tool, prompt, agent.

MCP servers

{
  "mcpServers": {
    "plugin-database": {
      "command": "${CLAUDE_PLUGIN_ROOT}/servers/db-server",
      "args": ["--config", "${CLAUDE_PLUGIN_ROOT}/config.json"],
      "env": { "DB_PATH": "${CLAUDE_PLUGIN_ROOT}/data" }
    }
  }
}

Plugin MCP server'ları plugin etkinleştirildiğinde otomatik başlar.

Kendi MCP tool'unu hook'la yakalamak Plugin'in kendi MCP server'ını hedefleyen hook'lar scoped ad kullanmak zorundadır. Tool matcher'ları için mcp__plugin_<plugin-adi>_<server-adi>__<tool>, mcp_tool hook'unun server alanı için plugin:<plugin-adi>:<server-adi>. Çıplak server anahtarıyla yazılmış bir matcher hiçbir zaman tetiklenmez.

LSP servers

{
  "go": {
    "command": "gopls",
    "args": ["serve"],
    "extensionToLanguage": { ".go": "go" }
  }
}

Zorunlu alanlar command ve extensionToLanguage. Python, TypeScript, Rust, Go, Java, C/C++, PHP gibi yaygın diller için resmî marketplace'te hazır LSP plugin'leri var — kendi LSP plugin'ini yalnızca kapsanmayan diller için yaz. Dil sunucusu ikilisini plugin kurmaz, kullanıcı kendisi kurar.

Monitors, themes, bin/, settings.json

  • Monitors (monitors/monitors.json): oturum boyunca çalışan bir komutun her stdout satırını Claude'a bildirim olarak iletir. name, command, description zorunlu; when ile "always" veya "on-skill-invoke:<skill-adi>" seçilir. Yalnızca etkileşimli CLI oturumlarında çalışır, hook'larla aynı güven seviyesindedir.
  • Themes (themes/): base preset + seyrek overrides haritası. /theme içinde görünür, salt okunurdur.
  • bin/: buradaki dosyalar plugin etkinken Bash tool'un PATH'ine eklenir; Claude çıplak komut olarak çağırabilir.
  • settings.json: yalnızca agent ve subagentStatusLine anahtarları desteklenir. agent ile plugin, kendi agent'ını ana thread olarak etkinleştirip Claude Code'un varsayılan davranışını değiştirebilir.

07 Mutlak yol yazarsan kırılır

Marketplace'ten kurulan plugin'ler yerinde kullanılmaz — ~/.claude/plugins/cache altına kopyalanır ve her sürüm ayrı bir klasördür. Bu yüzden plugin'in kendi dosyalarına makine üstündeki gerçek yolla değil, değişkenle erişmelisin.

DeğişkenNeye çözülürNe için
${CLAUDE_PLUGIN_ROOT}Plugin'in kurulum dizininin mutlak yoluPakete gömülü script, binary ve config dosyaları
${CLAUDE_PLUGIN_DATA}Güncellemeleri aşan kalıcı dizin (~/.claude/plugins/data/{id}/)node_modules, venv, üretilen kod, cache
${CLAUDE_PROJECT_DIR}Proje köküProjeye ait script ve config dosyaları

Üçü de hook süreçlerine, MCP ve LSP alt süreçlerine ortam değişkeni olarak geçer. Satır içi ikame ise bileşene göre değişir: skill ve agent içeriğinde her yerde, hook ve monitor komutlarında her yerde, MCP stdio server'larında command/args/env, HTTP tabanlı MCP server'larında url/headers/headersHelper, LSP'de command/args/env/workspaceFolder.

Plugin kökünün dışına çıkamazsın Kurulmuş bir plugin kendi dizininin dışındaki dosyalara erişemez. ../shared-utils gibi yollar kurulumdan sonra çalışmaz çünkü o dosyalar cache'e kopyalanmaz. Aynı marketplace içinde dosya paylaşman gerekiyorsa symlink kullan: plugin'in kendi dizini içine çözülen symlink korunur, aynı marketplace içindeki başka bir yere çözülen symlink'in hedefi kopyalanır, marketplace dışına çıkan symlink güvenlik gereği atlanır.

Manifest yolları: hangisi ekler, hangisi değiştirir?

  • Varsayılanın yerine geçer: commands, agents, workflows, outputStyles, experimental.themes, experimental.monitors. Varsayılanı korumak istiyorsan listeye açıkça ekle: "commands": ["./commands/", "./extras/"].
  • Varsayılana eklenir: skills. skills/ klasörü her zaman taranır, manifest'te yazdıkların onun yanına yüklenir.
  • Kendi birleştirme kuralı olanlar: hooks, mcpServers, lspServers.
  • Tüm yollar plugin köküne göreli ve ./ ile başlamalı. Tek istisna: skills alanı "." değerini de kabul eder.
Güncelleme sonrası yol değişir ${CLAUDE_PLUGIN_ROOT} plugin her güncellendiğinde değişir; oraya kalıcı durum yazma. Eski sürümün dizini yaklaşık iki hafta diskte kalır (açık oturumlar hata almasın diye), sonra temizlenir. Bir plugin oturum ortasında güncellenirse hook'lar, monitor'lar ve server'lar eski yolu kullanmaya devam eder; /reload-plugins hook'ları, MCP ve LSP server'larını yeni yola geçirir, monitor'lar için oturumu yeniden başlatman gerekir.

08 Yayınlamadan önce: --plugin-dir

Plugin'i test etmek için marketplace kurmana, hatta kurulum yapmana gerek yok.

# Klasörden yükle
claude --plugin-dir ./my-plugin

# Zip arşivinden de olur
claude --plugin-dir ./my-plugin.zip

# Birden çok plugin'i aynı anda
claude --plugin-dir ./plugin-one --plugin-dir ./plugin-two

# CI çıktısı gibi uzakta duran bir zip'i tek oturumluk yükle
claude --plugin-url https://example.com/my-plugin.zip

--plugin-dir ile yüklenen bir plugin, aynı adlı kurulu bir marketplace plugin'inin önüne geçer — yani kurulu sürümü kaldırmadan değişikliklerini deneyebilirsin. İstisna: yönetilen ayarların zorla açtığı veya kapattığı plugin'leri --plugin-dir geçersiz kılamaz.

Değişiklikleri yeniden yüklemek

/reload-plugins

Plugin'leri, skill'leri, agent'ları, hook'ları, plugin MCP ve LSP server'larını yeniden yükler. Yeniden yükleme prompt cache'ini geçersiz kılacaksa komut uyarır ve uygulamaz; --force ile zorlarsın.

Yanıltıcı çıktı /reload-plugins özetindeki skill sayacı yalnızca commands/ klasörünü sayar. Yani skills/ altındaki skill'lerin yeniden yüklendiği halde özet 0 skills yazabilir. Bu bir hata değil; skill'i çağırarak doğrula.

Doğrulama ve tanılama

# plugin.json + skill/agent/command frontmatter + hooks.json şema kontrolü
claude plugin validate ./my-plugin
claude plugin validate ./my-plugin --strict   # uyarıları hata say (CI için)

# Marketplace dizininden çalıştırınca marketplace.json'u denetler
claude plugin validate .

# Yükleme ayrıntıları: hangi plugin yüklendi, hangi bileşen kaydedildi, ne hata verdi
claude --debug

# Bileşen envanteri + oturuma eklediği tahmini token maliyeti
claude plugin details my-plugin

09 Marketplace dediğin tek bir JSON

Marketplace, plugin'lerini ve nerede durduklarını listeleyen bir katalogdur. Repo kökünde .claude-plugin/marketplace.json olarak durur; barındırma işini GitHub, GitLab veya herhangi bir git sunucusu yapar.

{
  "name": "company-tools",
  "owner": {
    "name": "DevTools Team",
    "email": "devtools@example.com"
  },
  "description": "Internal Claude Code plugins",
  "plugins": [
    {
      "name": "code-formatter",
      "source": "./plugins/formatter",
      "description": "Automatic code formatting on save",
      "version": "2.1.0"
    },
    {
      "name": "deployment-tools",
      "source": { "source": "github", "repo": "company/deploy-plugin" },
      "description": "Deployment automation tools"
    }
  ]
}

Plugin girdilerinde zorunlu olan yalnızca name ve source'tur. Girdi ayrıca manifest şemasındaki her alanı (description, version, author, commands, agents, hooks, mcpServers…) ve marketplace'e özgü category, tags, strict, relevance, defaultEnabled alanlarını kabul eder.

Tek marketplace adı, çok plugin Her kullanıcı bir ada karşılık yalnızca bir marketplace kaydedebilir; aynı adla ikinci bir marketplace eklemek ilkinin yerine geçer. Birden çok plugin yayınlayacaksan hepsini tek bir marketplace.json içinde listele.

strict: manifest mi, katalog mu otorite?

DeğerDavranış
true (varsayılan)plugin.json otoritedir. Marketplace girdisi üstüne bileşen ekleyebilir; iki kaynak birleştirilir
falseMarketplace girdisi tanımın tamamıdır. Plugin'in kendi plugin.json'ı da bileşen tanımlıyorsa bu bir çakışmadır ve plugin yüklenmez

strict: false, marketplace işletmecisinin ham dosyalardan hangilerinin skill/agent/hook olarak açığa çıkacağına kendisi karar vermek istediği durumlar içindir.

# Claude Code içinden:
/plugin marketplace add ./my-marketplace
/plugin install quality-review-plugin@my-plugins
/quality-review-plugin:quality-review

Katalogdaki her girdinin source alanı, o plugin'in dosyalarının nereden alınacağını söyler. Marketplace kaynağı (kataloğun kendisi nereden gelir) ile plugin kaynağı (tek bir plugin nereden gelir) farklı şeylerdir ve bağımsız sabitlenir.

Git tabanlı kaynaklarda ref ve sha birlikte verilirse geçerli olan sha'dır; Claude Code o commit'i doğrudan çeker. GitHub, GitLab ve Bitbucket'ta bu, ref silinmiş olsa bile kurulumun çalışması demektir.

URL marketplace + göreli yol = çalışmaz Marketplace'ini doğrudan bir marketplace.json URL'i olarak dağıtırsan Claude Code yalnızca o dosyayı indirir; "./plugins/x" gibi göreli kaynaklar "path not found" verir. URL ile dağıtacaksan plugin kaynaklarını github, npm, git URL veya archive yap — ya da marketplace'i git repo'su olarak yayınla.

11 version bir alan değil, güncelleme sinyali

Claude Code plugin'in sürümünü cache anahtarı olarak kullanır. /plugin update veya otomatik güncelleme çalıştığında, hesapladığı sürüm kuruluyla aynıysa güncellemeyi atlar. Sürüm şu sıraya göre çözülür:

  • Plugin'in plugin.json'ındaki version
  • Marketplace girdisindeki version
  • Kaynağın git commit SHA'sı — github, url, git-subdir ve git tabanlı marketplace içindeki göreli yollar için
  • archive kaynaklarında sha256 sabiti veya indirilen dosyanın digest'i (ilk 12 karaktere kısaltılır)
  • unknown — npm kaynakları ve git repo'su içinde olmayan yerel dizinler için
YaklaşımNasılGüncelleme davranışıKime uygun
Açık sürüm plugin.json'a "version": "2.1.0" Kullanıcılar yalnızca bu alanı artırdığında güncelleme alır Yayınlanmış, düzenli sürüm döngüsü olan plugin'ler
Commit SHA version'ı her iki yerden de çıkar Kaynağın commit'i her değiştiğinde güncelleme gelir Aktif geliştirilen iç/ekip plugin'leri
Digest archive kaynağı, version yok sha256 sabiti varsa onu değiştirince, yoksa zip'in içeriği değişince Statik sunucu / artifact repo'suna zip olarak yayınlananlar
Sessiz güncellenmeme "version": "1.0.0" yazıp yeni commit'ler push edersen mevcut kullanıcılar cache'teki kopyayı kullanmaya devam eder — Claude Code aynı sürümü gördüğü için /plugin update "already at the latest version" der. Her yayında alanı artır ya da hiç yazma. Ayrıca version'ı hem plugin.json'da hem marketplace girdisinde tanımlamaktan kaçın: Claude Code her zaman uyarı vermeden plugin.json'dakini kullanır, dolayısıyla unutulmuş bir manifest sürümü katalogdakini maskeler.

Açık sürüm kullanacaksan semantic versioning uygula: kırıcı değişiklikte MAJOR, yeni özellikte MINOR, hata düzeltmede PATCH. Değişiklikleri CHANGELOG.md'ye yaz. Sürüm etiketi oluşturmak için:

claude plugin tag              # bulunduğun dizindeki plugin'i etiketle
claude plugin tag --push       # etiketi remote'a gönder
claude plugin tag --dry-run    # ne yapacağını göster

Stable / latest kanalları

İki ayrı marketplace kurup aynı repo'nun farklı ref'lerine bakmalarını sağlayarak sürüm kanalı oluşturabilirsin; sonra yönetilen ayarlarla farklı kullanıcı gruplarına farklı marketplace atarsın. Şart: iki kanal farklı sürüme çözülmeli. Açık sürüm kullanıyorsan her sabitlenmiş ref'te plugin.json farklı bir version ilan etmeli.

12 Ekibe dağıtmak: kimse elle kurmasın

Plugin'i kurmak bir kapsam (scope) seçmektir; kapsam, plugin'in hangi ayar dosyasına yazılacağını ve dolayısıyla kimin kullanacağını belirler.

KapsamAyar dosyasıKullanım
user (varsayılan)~/.claude/settings.jsonTüm projelerde geçerli kişisel plugin'ler
project.claude/settings.jsonSürüm kontrolüyle paylaşılan ekip plugin'leri
local.claude/settings.local.jsonYalnızca bu repo'da, yalnızca sende
managedYönetilen ayarlarYönetici tarafından kurulan, salt okunur plugin'ler
 
claude plugin install formatter@my-marketplace
claude plugin install formatter@my-marketplace --scope project
claude plugin uninstall formatter@my-marketplace --scope project --keep-data
claude plugin list --json
claude plugin details formatter

Repo'yu açan herkese teklif edilsin

Projenin .claude/settings.json dosyasına marketplace'i yazarsan, ekip arkadaşların klasöre güven verdiğinde Claude Code onlara kurulumu teklif eder:

{
  "extraKnownMarketplaces": {
    "company-tools": {
      "source": { "source": "github", "repo": "your-org/claude-plugins" }
    }
  },
  "enabledPlugins": {
    "code-formatter@company-tools": true,
    "deployment-tools@company-tools": true
  }
}
"Etkin" kurulu demek değil Yalnızca projenin .claude/settings.json'ı tarafından etkinleştirilen ve GitHub/npm gibi dış bir kaynaktan gelen bir plugin, ekip arkadaşın onu kurana kadar yüklenmez. Claude Code plugin'i "kurulu değil" olarak raporlar ve çalıştırılacak claude plugin install komutunu gösterir.

Özel repo'lar

/plugin marketplace add, /plugin install ve elle çalıştırdığın güncellemeler senin git kimlik yardımcılarını (credential helper) kullanır — gh auth login, macOS Keychain veya git-credential-store terminalde nasıl çalışıyorsa öyle çalışır. Ama arka plandaki otomatik güncelleme varsayılan olarak kimlik yardımcılarını devre dışı bırakır; HTTPS üzerinden özel repo'ya kimlik doğrulayamaz (SSH remote'ları etkilenmez). İki ayar bu davranışı öngörülebilir kılar:

  • CLAUDE_CODE_PLUGIN_KEEP_MARKETPLACE_ON_FAILURE=1 — pull başarısız olunca klonu silip yeniden çekmek yerine mevcut kopyayı koru. Çevrimdışı/airgapped ortamlar için de doğru ayar budur.
  • gh auth setup-git ile bir credential helper yapılandır ki yeniden klonlama kimlik doğrulayabilsin.
  • Büyük repo'larda 120 saniyelik git zaman aşımına takılıyorsan: CLAUDE_CODE_PLUGIN_GIT_TIMEOUT_MS=300000.

Container ve CI: hiç klonlamadan başlat

İmaj oluştururken plugin'leri bir tohum dizinine kurup çalışma zamanında oradan okutabilirsin:

CLAUDE_CODE_PLUGIN_CACHE_DIR=/opt/claude-seed claude plugin marketplace add your-org/plugins
CLAUDE_CODE_PLUGIN_CACHE_DIR=/opt/claude-seed claude plugin install my-tool@your-plugins
# Çalışma zamanında:
export CLAUDE_CODE_PLUGIN_SEED_DIR=/opt/claude-seed

Tohum dizini salt okunurdur, otomatik güncelleme kapalıdır ve her açılışta kullanıcının yapılandırmasındaki eşleşen kayıtların üstüne yazar. Bir tohum plugin'ini istemiyorsan marketplace'i kaldırmak yerine /plugin disable kullan.

Yöneticiler için: kaynak kısıtlama

Yönetilen ayarlardaki strictKnownMarketplaces kullanıcıların hangi marketplace'leri ekleyebileceğini sınırlar. Tanımsızsa kısıtlama yok; boş dizi ([]) resmî Anthropic marketplace'i dahil her şeyi engeller; liste verilirse yalnızca birebir eşleşenler eklenebilir.

{
  "strictKnownMarketplaces": [
    { "source": "github", "repo": "acme-corp/approved-plugins" },
    { "source": "hostPattern", "hostPattern": "^github\\.example\\.com$" }
  ]
}

Eşleştirme URL'leri normalize etmez: sondaki eğik çizgi, .git uzantısı veya ssh:// ile https:// farklı değerlerdir. Kurumun marketplace'i birden çok URL biçimiyle klonlanabiliyorsa düz URL yerine hostPattern kullan. Ayrıca bu ayar marketplace'i kaydetmez, sadece izin verir — otomatik kaydolması için aynı dosyada extraKnownMarketplaces'e de ekle.

Otomatik güncelleme Claude Code, oturum başladıktan sonra en fazla on dakikalık rastgele bir gecikmeyle marketplace ve plugin güncellemelerini arka planda kontrol eder; çalışan oturum yüklediği sürümleri kullanmaya devam eder. Resmî Anthropic marketplace'lerinde otomatik güncelleme açık, üçüncü taraf ve yerel geliştirme marketplace'lerinde kapalı gelir. Claude Code'un kendi güncellemesini kapatıp plugin güncellemelerini açık tutmak için: DISABLE_AUTOUPDATER=1 ile birlikte FORCE_AUTOUPDATE_PLUGINS=1.

13 Herkese açmak: host et, sonra submit et

Plugin'in hazır olduğunda yayın süreci üç adımdır ve ilki teknik bile değildir.

  • Dokümante et. Kurulum ve kullanım anlatan bir README.md ekle.
  • Sürümleme stratejini seç. Açık version mı, commit SHA'sı mı — bölüm 11.
  • Marketplace'e koy. Kendi marketplace.json'ını bir git repo'suna push et; kullanıcılar /plugin marketplace add owner/repo ile ekler.
  • Başkalarına test ettir. Geniş dağıtımdan önce ekipten birkaç kişi kursun.

Ekip içinde kalmasını istiyorsan marketplace'i özel bir repo'da tut — akış tamamen aynıdır, yalnızca kimlik doğrulama devreye girer (bölüm 12).

Topluluk marketplace'ine başvuru

Anthropic iki açık marketplace işletir:

  • claude-plugins-official — Anthropic'in derlediği küratörlü set. Claude Code'u ilk kez etkileşimli başlattığında kendiliğinden kaydolur. Kaydolmadıysa: claude plugin marketplace add anthropics/claude-plugins-official. Buraya başvuru süreci yoktur; içerik Anthropic'in takdirindedir.
  • claude-community — inceleme ve otomatik güvenlik taramasından geçen üçüncü taraf plugin'lerin geldiği yer. Kullanıcılar /plugin marketplace add anthropics/claude-plugins-community ile ekler, @claude-community son ekiyle kurar.

Topluluk marketplace'i için başvuru formları: claude.ai üzerinden (Team veya Enterprise organizasyonu ve directory yönetim yetkisi gerekir) veya Console üzerinden (bireysel yazarlar için).

Başvurmadan önce claude plugin validate ./your-plugin çalıştır — inceleme hattı her başvuruda aynı kontrolü yapar. Onaylanan plugin'ler anthropics/claude-plugins-community kataloğunda belirli bir commit SHA'sına sabitlenir ve sen yeni commit push ettikçe CI sabiti kendiliğinden günceller. Katalog gece senkronize olduğu için onay ile plugin'in kurulabilir hale gelmesi arasında gecikme olabilir.

14 Üç senaryo, üç plugin

Senaryo 1 — Ekibin commit akışını standartlaştırmak

Problem: Herkesin commit mesajı farklı biçimde; birkaç kişi .claude/commands/commit.md dosyasını birbirine kopyalayıp duruyor ve kopyalar birbirinden ayrışmış durumda.

Çözüm: Tek skill'lik bir plugin + repo'ya yazılmış proje kapsamı.

team-git/
├── .claude-plugin/plugin.json
└── skills/
    ├── commit/SKILL.md
    └── pr/SKILL.md
// .claude-plugin/plugin.json
{ "name": "team-git", "description": "Ekip commit ve PR akisi" }

Marketplace repo'suna koy, sonra projenin .claude/settings.json'ına extraKnownMarketplaces + enabledPlugins yaz. Ekip repo'yu klonlayıp klasöre güven verdiğinde kurulum teklif edilir; herkeste /team-git:commit aynı şeyi yapar.

Sürümleme: version alanını hiç yazma. Marketplace git'te olduğu için her commit yeni sürüm sayılır ve ekip düzeltmeleri otomatik alır.

Senaryo 2 — Şirket içi API'ye bağlanan MCP plugin'i

Problem: Claude'un iç deployment API'nizi sorgulaması gerekiyor. Herkesin .mcp.json yazması, üstüne bir de kendi token'ını doğru yere koyması gerekiyor.

Çözüm: MCP server'ı paketleyen ve token'ı userConfig ile soran bir plugin.

{
  "name": "deploy-api",
  "version": "1.3.0",
  "defaultEnabled": false,
  "userConfig": {
    "api_endpoint": {
      "type": "string", "title": "API endpoint",
      "description": "Deployment API base URL", "required": true
    },
    "api_token": {
      "type": "string", "title": "API token",
      "description": "Personal access token", "sensitive": true
    }
  }
}
// .mcp.json
{
  "mcpServers": {
    "deploy": {
      "command": "node",
      "args": ["${CLAUDE_PLUGIN_ROOT}/server.js"],
      "env": {
        "API_URL": "${user_config.api_endpoint}",
        "API_TOKEN": "${user_config.api_token}",
        "NODE_PATH": "${CLAUDE_PLUGIN_DATA}/node_modules"
      }
    }
  }
}

Bağımlılıkları güncellemeleri aşan dizine bir kez kur; SessionStart hook'u package.json değiştiğinde yeniden kurar:

{
  "hooks": {
    "SessionStart": [{ "hooks": [{
      "type": "command",
      "command": "diff -q \"${CLAUDE_PLUGIN_ROOT}/package.json\" \"${CLAUDE_PLUGIN_DATA}/package.json\" >/dev/null 2>&1 || (cd \"${CLAUDE_PLUGIN_DATA}\" && cp \"${CLAUDE_PLUGIN_ROOT}/package.json\" . && npm install)"
    }] }]
  }
}

Neden defaultEnabled: false: plugin dış bir servise bağlanıyor ve token istiyor; kullanıcı bilinçli olarak açsın. Neden açık version: API sözleşmesi değiştiğinde kırıcı sürümü işaretlemen gerekiyor.

Senaryo 3 — Kuralı rica etmeyi bırakmak

Problem: CLAUDE.md'de "migration dosyalarını elle düzenleme" yazıyor ama bu bir rica; bazen uyuluyor bazen uyulmuyor.

Çözüm: Kuralı zorlayan bir hook'u ve ihlali inceleyen bir agent'ı aynı pakette dağıt.

db-guard/
├── .claude-plugin/plugin.json
├── hooks/hooks.json
├── agents/migration-reviewer.md
└── scripts/block-migration-edit.sh
// hooks/hooks.json
{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Write|Edit",
      "hooks": [{
        "type": "command",
        "command": "\"${CLAUDE_PLUGIN_ROOT}\"/scripts/block-migration-edit.sh"
      }]
    }]
  }
}

Script'i chmod +x yapmayı unutma — hook'un sessizce çalışmamasının bir numaralı sebebi budur. Test ederken claude --plugin-dir ./db-guard ile aç, Claude'a bir migration dosyası düzenlet ve engellendiğini gör. Dağıtımı project kapsamında yap: kural repo'ya ait, kişiye değil.

Yayına almadan önce kontrol listesi

  • .claude-plugin/ içinde yalnızca plugin.json var.
  • name kebab-case, ASCII ve kalıcı olmasını kabul ettiğin bir ad.
  • Plugin'e ait tüm yollar ./ ile göreli veya ${CLAUDE_PLUGIN_ROOT} ile mutlak; ../ yok.
  • Hook script'leri çalıştırılabilir ve shebang satırı doğru.
  • claude plugin validate ./plugin --strict temiz geçiyor.
  • Temiz bir oturumda --plugin-dir ile denendi: skill'ler çağrıldı, agent'lar /context'te göründü, hook'lar gerçekten tetiklendi.
  • Sürüm stratejisi seçildi ve version iki yerde birden tanımlı değil.
  • claude plugin details ile always-on token maliyetine bakıldı — her oturuma eklenen yükü biliyorsun.
  • README.md ve (açık sürüm kullanıyorsan) CHANGELOG.md var.
