01 Ekranın dibinde tam olarak ne var?

Statusline, Claude Code arayüzünün en altında duran ve senin yapılandırdığın herhangi bir shell script'ini çalıştıran bir çubuk. Akış üç adımdan ibaret: Claude Code oturum verisini JSON olarak script'in stdin'ine yazar, script okuduğunu işleyip stdout'a bir şeyler basar, Claude Code o çıktıyı olduğu gibi ekrana yansıtır. Arada şablon, tema motoru veya sabit alan listesi yok.

Bu satır kendi satırında render olur ve alttaki hazır footer rozetlerinin yerini almaz, onların üstüne eklenir. Konuşmada geçen bir ID'yi tıklanabilir rozete çevirmek istiyorsan script yazmana gerek yok; onun için ayrı bir ayar var: footerLinksRegexes.

Maliyeti yok Statusline tamamen yerelde çalışır ve API token harcamaz. İstediğin kadar sık güncellenmesi faturana yansımaz — tek maliyeti script'inin CPU süresi.

Satır her zaman görünmez: autocomplete önerileri, yardım menüsü ve permission prompt'ları gibi bazı arayüz etkileşimleri sırasında geçici olarak gizlenir. Ayrıca sağ tarafını sistem bildirimleriyle paylaşır — MCP sunucu hataları, auto-update mesajları, "context azaldı" uyarısı gibi geçici bildirimler aynı satırda dolaşır. Verbose mod açıksa buraya bir de token sayacı eklenir. Dar terminallerde bunlar senin çıktını kırpabilir.

İki sessiz kapatıcı Statusline bir shell komutu çalıştırdığı için hook'larla aynı güven kapısına tabidir. Bulunduğun klasör için workspace trust dialog'unu kabul etmediysen satır boş kalır. Ayrıca ayarlarında disableAllHooks: true varsa statusline da devre dışı kalır.

02 /statusline yaz, gerisini o kursun

Uçtan uca en kısa yol bu. /statusline komutu doğal dil talimatı kabul eder: ne görmek istediğini yazarsın, Claude Code ~/.claude/ altında script dosyasını üretir ve ayarlarını kendisi günceller. Kurulum sırasında dosya düzenleme izni isterse onaylaman yeterli.

/statusline show model name and context percentage with a progress bar

Talimatı Türkçe de yazabilirsin. Aşağıdaki tablo "neler istenebilir"in bir haritası — sol sütundaki her istek, sağ sütundaki JSON alanlarına ya da script'in çalıştıracağı komutlara karşılık gelir:

Ne istersinArka planda ne kullanılır

"Bulunduğum klasör ve git branch'i görünsün"workspace.current_dir + git branch --show-current
"Bu oturum kaç dolar oldu, kaç dakikadır açık"cost.total_cost_usd, cost.total_duration_ms
"5 saatlik ve haftalık kotamın ne kadarını yaktım"rate_limits.five_hour, rate_limits.seven_day
"Açık PR varsa numarası ve review durumu yazsın"pr.number, pr.review_state
"Hangi effort seviyesinde ve thinking açık mı, göreyim"effort.level, thinking.enabled, fast_mode
"Aynı anda üç oturum açıyorum, hangisi hangisi belli olsun"session_name, workspace.repo.name, worktree.name

Kaldırmak da aynı komutla: /statusline delete, /statusline clear ya da "remove it" gibi bir talimat statusline'ı siler. Dilersen settings.json içindeki statusLine alanını elle de silebilirsin.

Ne zaman elle kurmalı /statusline hızlı, ama ürettiği script sende kalır. Script'i versiyon kontrolüne almak, takımla paylaşmak veya cache/hata yönetimi gibi ince ayarlar yapmak istiyorsan bir sonraki bölümdeki elle kurulum daha net.

03 Elle kurmak: script + settings.json

Üç adım: script'i yaz, çalıştırılabilir yap, ayarlara ekle.

1 — Script (~/.claude/statusline.sh)

#!/bin/bash
# Claude Code'un stdin'e yazdığı JSON'u tek seferde oku
input=$(cat)

# Alanları jq ile çıkar ("// 0" null gelirse yedek değer verir)
MODEL=$(echo "$input" | jq -r '.model.display_name')
DIR=$(echo "$input" | jq -r '.workspace.current_dir')
PCT=$(echo "$input" | jq -r '.context_window.used_percentage // 0' | cut -d. -f1)

# ${DIR##*/} yolun sadece son klasör adını verir
echo "[$MODEL] 📁 ${DIR##*/} | ${PCT}% context"

2 — Çalıştırılabilir yap

chmod +x ~/.claude/statusline.sh

3 — Ayarlara ekle

Kullanıcı ayarların (~/.claude/settings.json) veya proje ayarların içine:

{
  "statusLine": {
    "type": "command",
    "command": "~/.claude/statusline.sh",
    "padding": 2
  }
}

command bir shell içinde çalışır, dolayısıyla dosya yolu yerine doğrudan tek satırlık bir komut da verebilirsin. Ayrı script dosyası istemiyorsan:

{
  "statusLine": {
    "type": "command",
    "command": "jq -r '\"[\\(.model.display_name)] \\(.context_window.used_percentage // 0)% context\"'"
  }
}
AlanNe yapar
typeZorunlu, değeri "command".
commandÇalıştırılacak script yolu ya da inline shell komutu.
paddingİçeriğe karakter cinsinden ek yatay boşluk. Varsayılan 0. Arayüzün kendi boşluğuna eklenir, yani terminal kenarından mutlak uzaklık değil göreli girinti ayarlar.
refreshIntervalOlay tabanlı güncellemelere ek olarak komutu her N saniyede bir tekrar çalıştırır. Minimum 1. Saat gibi zamana bağlı bir şey gösteriyorsan ya da ana oturum boştayken arka plan subagent'ları git durumunu değiştiriyorsa gerekir. Yazmazsan sadece olaylarda çalışır.
hideVimModeIndicatortrue yaparsan prompt'un altındaki hazır -- INSERT -- yazısı gizlenir. Vim modunu kendi script'inde vim.mode ile bastığında iki kere görünmesin diye.
Hemen görünmeyebilir Ayarlar otomatik yeniden yüklenir, ancak değişiklik bir sonraki etkileşimine kadar ekrana yansımaz. Bir mesaj gönder, satır yenilensin.

05 context_window'u yanlış okumak kolay

Statusline'ın en çok istenen içeriği context doluluğu, ve tam da burada birkaç ince nokta var.

  • Yüzde sadece input'tan hesaplanır. used_percentage şu toplamı kullanır: input_tokens + cache_creation_input_tokens + cache_read_input_tokens. output_tokens dahil değildir. Yüzdeyi current_usage'dan kendin hesaplayacaksan aynı formülü kullan, yoksa iki rakam tutmaz.
  • total_input_tokens artık kümülatif değil. v2.1.132'den itibaren bu alanlar oturum toplamını değil, şu anda context'te olan token'ları gösterir. İlk API yanıtından önce ikisi de 0.
  • current_usage null olabilir. Oturumun ilk API çağrısından önce ve /compact'ten sonra bir sonraki API çağrısına kadar null gelir. Yüzde alanları da oturumun başında null olabilir.
  • exceeds_200k_tokens sabit eşiktir. Modelin gerçek penceresi 1M olsa bile bu bayrak 200k'yı ölçer.
/context ile aynı olmayabilir Statusline'daki yüzde ile /context çıktısı farklı anlarda hesaplandığı için sapabilir. En basit ve tutarlı gösterim için used_percentage'i olduğu gibi kullan.

Cache alanlarını ayrı ayrı göstermek istersen current_usage tam da bunun için var — taze input ile cache okumasını ayırmak, prompt cache'in işe yarayıp yaramadığını canlı görmenin en ucuz yolu.

06 Script tam olarak ne zaman koşuyor?

Script'in bir kere oturum başlarken çalışır — bir oturumu resume ettiğinde de dahil. Sonrasında şu olaylarda tekrar çalışır:

  • Yeni bir asistan mesajı geldiğinde
  • /compact bittiğinde
  • Permission mode değiştiğinde
  • Vim modu değiştiğinde
  • Ayarladıysan, refreshInterval zamanlayıcısı dolduğunda

Güncellemeler 300 ms debounce edilir: hızlı değişiklikler tek bir çalıştırmada toplanır. Script'in hâlâ çalışırken yeni bir tetikleyici gelirse çalışan script iptal edilir. Script dosyasını düzenlersen değişiklik bir sonraki tetikleyicide devreye girer.

Sessiz oturumlar Olay tabanlı tetikleyiciler ana oturum boştayken susar — örneğin bir koordinatör arka plandaki subagent'ları beklerken. Saat, zamanlayıcı veya dışarıdan beslenen bir bölüm gösteriyorsan refreshInterval ile sabit periyotta da çalıştır.

Bir de genişlik meselesi var: Claude Code script'inin çıktısını yakalar, doğrudan terminale bağlamaz. Bu yüzden tput cols ve dil seviyesindeki genişlik tespitleri script'in içinden terminal boyutunu okuyamaz. Bunun yerine COLUMNS ve LINES ortam değişkenlerini oku — Claude Code script'i çalıştırmadan önce bunları güncel terminal ölçüleriyle doldurur (v2.1.153+).

Küçük bir tarihçe notu: v2.1.216 öncesinde bir oturumu resume etmek komutu kısa aralıkla iki kez çalıştırıyordu, bu yüzden ilk sonuç ekranda titreyip yerini ikinciye bırakabiliyordu.

07 Senaryo defteri

Aşağıdakiler kopyalayıp ~/.claude/statusline.sh (ya da .py) olarak kaydedip chmod +x yapabileceğin bitmiş örnekler. Bash sürümleri JSON'u jq ile ayrıştırır; Python ve Node'un kendi JSON desteği vardır.

A — "Sadece nerede olduğumu ve ne kadar yer kaldığını göreyim"

En sade kurulum. Model adı, klasör adı, context yüzdesi. Bölüm 3'teki script'in aynısı; ilk statusline'ın için doğru başlangıç.

B — "Context dolmadan önce fark edeyim" — bar

10 karakterlik bir dolum çubuğu, yüzdeyi göz kararı okunur hale getirir.

#!/bin/bash
input=$(cat)

MODEL=$(echo "$input" | jq -r '.model.display_name')
PCT=$(echo "$input" | jq -r '.context_window.used_percentage // 0' | cut -d. -f1)

# printf -v ile boşluk dizisi üret, sonra her boşluğu blok karakterine çevir
BAR_WIDTH=10
FILLED=$((PCT * BAR_WIDTH / 100))
EMPTY=$((BAR_WIDTH - FILLED))
BAR=""
[ "$FILLED" -gt 0 ] && printf -v FILL "%${FILLED}s" && BAR="${FILL// /▓}"
[ "$EMPTY" -gt 0 ] && printf -v PAD "%${EMPTY}s" && BAR="${BAR}${PAD// /░}"

echo "[$MODEL] $BAR $PCT%"

Python karşılığı çok daha kısa:

#!/usr/bin/env python3
import json, sys

data = json.load(sys.stdin)
model = data['model']['display_name']
# "or 0" null değeri yakalar
pct = int(data.get('context_window', {}).get('used_percentage', 0) or 0)

filled = pct * 10 // 100
bar = '▓' * filled + '░' * (10 - filled)

print(f"[{model}] {bar} {pct}%")

C — "Bu oturum bana kaça mal oldu?"

Deneysel bir işi ne kadar uzattığını görmenin en doğrudan yolu. total_cost_usd istemci tarafı bir tahmindir, faturayla birebir tutmayabilir.

#!/bin/bash
input=$(cat)

MODEL=$(echo "$input" | jq -r '.model.display_name')
COST=$(echo "$input" | jq -r '.cost.total_cost_usd // 0')
DURATION_MS=$(echo "$input" | jq -r '.cost.total_duration_ms // 0')

COST_FMT=$(printf '$%.2f' "$COST")
DURATION_SEC=$((DURATION_MS / 1000))
MINS=$((DURATION_SEC / 60))
SECS=$((DURATION_SEC % 60))

echo "[$MODEL] 💰 $COST_FMT | ⏱️ ${MINS}m ${SECS}s"

D — "Haftalık kotamı bilmeden yakmayayım"

Pro/Max aboneliğindeysen 5 saatlik ve 7 günlük pencerelerin doluluğu buradan gelir. Alan hiç gelmeyebileceği için // empty ile zarifçe düşmek şart.

#!/bin/bash
input=$(cat)

MODEL=$(echo "$input" | jq -r '.model.display_name')
# "// empty" alan yoksa hiçbir şey basmaz
FIVE_H=$(echo "$input" | jq -r '.rate_limits.five_hour.used_percentage // empty')
WEEK=$(echo "$input" | jq -r '.rate_limits.seven_day.used_percentage // empty')

LIMITS=""
[ -n "$FIVE_H" ] && LIMITS="5h: $(printf '%.0f' "$FIVE_H")%"
[ -n "$WEEK" ] && LIMITS="${LIMITS:+$LIMITS }7d: $(printf '%.0f' "$WEEK")%"

[ -n "$LIMITS" ] && echo "[$MODEL] | $LIMITS" || echo "[$MODEL]"

resets_at alanları Unix epoch saniyesi verir; "2 saat sonra sıfırlanıyor" gibi bir ifade istiyorsan bu değerden kendi hesabını yapman gerekir (tarih biçimlendirme komutları platforma göre değişir).

E — "Hangi branch'teyim, kaç dosya kirli, PR açık mı?"

Git bilgisi JSON'da hazır gelmez — branch ve değişiklik sayılarını script'in kendisi git çağırarak toplar. PR bilgisi ise JSON'dan gelir.

#!/bin/bash
input=$(cat)

MODEL=$(echo "$input" | jq -r '.model.display_name')
DIR=$(echo "$input" | jq -r '.workspace.current_dir')
PR_NUM=$(echo "$input" | jq -r '.pr.number // empty')
PR_STATE=$(echo "$input" | jq -r '.pr.review_state // empty')

GREEN='\033[32m'; YELLOW='\033[33m'; RESET='\033[0m'

GIT_INFO=""
if git rev-parse --git-dir > /dev/null 2>&1; then
    BRANCH=$(git branch --show-current 2>/dev/null)
    STAGED=$(git diff --cached --numstat 2>/dev/null | wc -l | tr -d ' ')
    MODIFIED=$(git diff --numstat 2>/dev/null | wc -l | tr -d ' ')
    GIT_INFO=" | 🌿 $BRANCH"
    [ "$STAGED" -gt 0 ] && GIT_INFO="${GIT_INFO} ${GREEN}+${STAGED}${RESET}"
    [ "$MODIFIED" -gt 0 ] && GIT_INFO="${GIT_INFO} ${YELLOW}~${MODIFIED}${RESET}"
fi

PR_INFO=""
[ -n "$PR_NUM" ] && PR_INFO=" | PR #${PR_NUM}${PR_STATE:+ (${PR_STATE})}"

echo -e "[$MODEL] 📁 ${DIR##*/}${GIT_INFO}${PR_INFO}"

F — "Şu an hangi ayarlarla çalışıyorum?"

Effort seviyesi, thinking, fast mode, output style ve agent adı tek satırda rozet gibi. Uzun oturumlarda /effort ile yaptığın değişikliği unutmamak için birebir.

#!/usr/bin/env python3
import json, sys

    parts.append("fast")

08 Renk, çok satır, tıklanabilir link

Script'in çıktısı düz metinle sınırlı değil. Üç şey mümkün:

  • Çok satır: her echo / print ayrı bir satır olarak görünür.
  • Renk: ANSI escape kodları (\033[32m yeşil gibi) — terminalin desteklemesi gerekir.
  • Link: OSC 8 escape dizileri metni tıklanabilir yapar (macOS'ta Cmd, Windows ve Linux'ta Ctrl + tık).
KodRenk
\033[31mkırmızı
\033[32myeşil
\033[33msarı
\033[36mcamgöbeği
\033[0msıfırla (her renkli parçadan sonra şart)

Aşağıdaki örnek üçünü birleştiriyor: eşiğe göre renk (70 altı yeşil, 70–89 sarı, 90+ kırmızı), bar ve iki satırlık yerleşim. Üst satır nerede olduğunu, alt satır ne kadar harcadığını söylüyor.

#!/bin/bash
input=$(cat)

MODEL=$(echo "$input" | jq -r '.model.display_name')
DIR=$(echo "$input" | jq -r '.workspace.current_dir')
COST=$(echo "$input" | jq -r '.cost.total_cost_usd // 0')
PCT=$(echo "$input" | jq -r '.context_window.used_percentage // 0' | cut -d. -f1)
DURATION_MS=$(echo "$input" | jq -r '.cost.total_duration_ms // 0')

CYAN='\033[36m'; GREEN='\033[32m'; YELLOW='\033[33m'; RED='\033[31m'; RESET='\033[0m'

# Bar rengini context doluluğuna göre seç
if [ "$PCT" -ge 90 ]; then BAR_COLOR="$RED"
elif [ "$PCT" -ge 70 ]; then BAR_COLOR="$YELLOW"
else BAR_COLOR="$GREEN"; fi

FILLED=$((PCT / 10)); EMPTY=$((10 - FILLED))
printf -v FILL "%${FILLED}s"; printf -v PAD "%${EMPTY}s"
BAR="${FILL// /█}${PAD// /░}"

MINS=$((DURATION_MS / 60000)); SECS=$(((DURATION_MS % 60000) / 1000))

BRANCH=""
git rev-parse --git-dir > /dev/null 2>&1 && BRANCH=" | 🌿 $(git branch --show-current 2>/dev/null)"

echo -e "${CYAN}[$MODEL]${RESET} 📁 ${DIR##*/}$BRANCH"
COST_FMT=$(printf '$%.2f' "$COST")
echo -e "${BAR_COLOR}${BAR}${RESET} ${PCT}% | ${YELLOW}${COST_FMT}${RESET} | ⏱️ ${MINS}m ${SECS}s"

Tıklanabilir repo linki

OSC 8 biçimi şöyle: \e]8;;URL\a + görünecek metin + \e]8;;\a. Bash'te echo -e yerine printf '%b' kullanmak escape'leri kabuklar arasında daha güvenilir yorumlar.

#!/bin/bash
input=$(cat)
MODEL=$(echo "$input" | jq -r '.model.display_name')

# git SSH URL'sini HTTPS'e çevir
REMOTE=$(git remote get-url origin 2>/dev/null | sed 's/git@github.com:/https:\/\/github.com\//' | sed 's/\.git$//')

if [ -n "$REMOTE" ]; then
    REPO_NAME=$(basename "$REMOTE")
    printf '%b' "[$MODEL] 🔗 \e]8;;${REMOTE}\a${REPO_NAME}\e]8;;\a\n"
else
    echo "[$MODEL]"
fi

Tıklanabilirlik terminale bağlı: iTerm2, Kitty ve WezTerm destekler, macOS'un Terminal.app desteklemez. Link metni görünüyor ama tıklanmıyorsa Claude Code terminalinin hyperlink desteğini tespit edememiş olabilir — Windows Terminal'de sık görülür. Başlatmadan önce zorla:

# bash

# PowerShell

Escape dizileri kırılgandır Karmaşık ANSI/OSC dizileri diğer arayüz güncellemeleriyle çakışırsa çıktı bozulabilir. Bozuk metin görüyorsan script'i düz metne indirerek dene: escape kodlu çok satırlı statusline'lar, tek satırlık düz metinden belirgin şekilde daha sorunludur. 09 Windows'ta bir tuzak var

Windows'ta Claude Code statusline komutunu Git Bash kuruluysa Git Bash üzerinden, kurulu değilse PowerShell üzerinden çalıştırır.

Ters bölü sessizce yiyor Git Bash tırnaksız ters bölü işaretlerini escape karakteri sayar. C:\Users\username\script.mjs gibi bir yol script çalıştırıcısına ayraçları silinmiş halde ulaşır ve komut görünür bir hata vermeden başarısız olur. command içindeki yolları düz bölü ile yaz. ~ kısayolu da çalışır ve Windows ev dizinine açılır.

PowerShell script'i kullanmak istiyorsan powershell üzerinden çağır — bu yöntem, komut ister Git Bash'ten ister PowerShell'den geçsin çalışır:

{
  "statusLine": {
    "type": "command",
    "command": "powershell -NoProfile -File C:/Users/username/.claude/statusline.ps1"
  }
}
# statusline.ps1
$input_json = $input | Out-String | ConvertFrom-Json
$cwd = $input_json.cwd
$model = $input_json.model.display_name
$used = $input_json.context_window.used_percentage
$dirname = Split-Path $cwd -Leaf

if ($used) {
    Write-Host "$dirname [$model] ctx: $used%"
} else {
    Write-Host "$dirname [$model]"
}

Git Bash kuruluysa doğrudan bir Bash script'i de çalıştırabilirsin. jq yüklü değilse basit alanlar için grep yeterli olur:

#!/usr/bin/env bash
input=$(cat)
cwd=$(echo "$input" | grep -o '"cwd":"[^"]*"' | cut -d'"' -f4)
model=$(echo "$input" | grep -o '"display_name":"[^"]*"' | cut -d'"' -f4)
dirname="${cwd##*[/\\]}"
echo "$dirname [$model]"

10 Yavaş script'i statusline affetmez

Script'in aktif oturumlarda sık çalışır. Büyük repolarda git status veya git diff gibi komutlar yavaştır ve yavaş script satırın güncellenmesini bloklar — ekranda bayat bilgi kalır. Çözüm: pahalı işi cache'le.

Cache dosyasının adı önemli Ad, aynı oturumun çağrıları arasında sabit, farklı oturumlar arasında benzersiz olmalı — yoksa farklı repolardaki eş zamanlı oturumlar birbirinin git durumunu okur. $$, os.getpid(), process.pid gibi süreç kimlikleri her çağrıda değişir ve cache'i işlevsiz bırakır. JSON'dan gelen session_id'yi kullan. 
#!/bin/bash
input=$(cat)

MODEL=$(echo "$input" | jq -r '.model.display_name')
DIR=$(echo "$input" | jq -r '.workspace.current_dir')
SESSION_ID=$(echo "$input" | jq -r '.session_id')

CACHE_FILE="/tmp/statusline-git-cache-$SESSION_ID"
CACHE_MAX_AGE=5  # saniye

cache_is_stale() {
    [ ! -f "$CACHE_FILE" ] || \
    # stat -c %Y (Linux) veya stat -f %m (macOS) son değişiklik zamanını basar.
    # Linux formu önce gelmeli: Linux'ta macOS formu başarısız olmadan önce
    # stdout'a rapor basar ve bu çıktı aritmetiği bozar.
    [ $(($(date +%s) - $(stat -c %Y "$CACHE_FILE" 2>/dev/null || stat -f %m "$CACHE_FILE" 2>/dev/null || echo 0))) -gt $CACHE_MAX_AGE ]
}

if cache_is_stale; then
    if git rev-parse --git-dir > /dev/null 2>&1; then
        BRANCH=$(git branch --show-current 2>/dev/null)
        STAGED=$(git diff --cached --numstat 2>/dev/null | wc -l | tr -d ' ')
        MODIFIED=$(git diff --numstat 2>/dev/null | wc -l | tr -d ' ')
        echo "$BRANCH|$STAGED|$MODIFIED" > "$CACHE_FILE"
    else
        echo "||" > "$CACHE_FILE"
    fi
fi

IFS='|' read -r BRANCH STAGED MODIFIED < "$CACHE_FILE"

if [ -n "$BRANCH" ]; then
    echo "[$MODEL] 📁 ${DIR##*/} | 🌿 $BRANCH +$STAGED ~$MODIFIED"
else
    echo "[$MODEL] 📁 ${DIR##*/}"
fi

İki pratik kural daha: çıktıyı kısa tut — çubuğun genişliği sınırlı, uzun çıktı kırpılır veya çirkin sarar. Ve script'i bağlamadan önce sahte girdiyle bağımsız test et.

Hazır çözümler Sıfırdan yazmak istemiyorsan topluluk projeleri var: temalar ve ek özelliklerle gelen ccstatusline ve starship-claude.

11 Subagent'ların kendi satırı

Ana statusline'ın kardeşi: subagentStatusLine ayarı, prompt'un altındaki agent panelinde görünen her subagent satırının gövdesini senin biçimlendirmene izin verir. Varsayılan ad · açıklama · token sayısı düzenini değiştirmek istediğinde kullanılır.

{
  "subagentStatusLine": {
    "type": "command",
    "command": "~/.claude/subagent-statusline.sh"
  }
}

Çalışma şekli ana statusline'dan farklı: komut her yenileme turunda bir kez çalışır ve görünen tüm subagent satırlarını tek bir JSON nesnesi olarak alır. Girdi, ortak hook alanlarına ek olarak kullanılabilir satır genişliğini veren columns alanını ve bir tasks dizisini içerir. Her görevde şunlar bulunur: id, name, type, status, description, label, startTime, model, effort, contextWindowSize, tokenCount, tokenSamples, cwd.

Çıktı biçimi de farklı: ezmek istediğin her satır için stdout'a bir JSON satırı yazarsın — {"id": "<task id>", "content": "<satır gövdesi>"}. content olduğu gibi render edilir; ANSI renkleri ve OSC 8 linkleri geçerlidir. Bir görevin id'sini hiç yazmazsan o satır varsayılan haliyle kalır; content'i boş string verirsen satır gizlenir.

#!/usr/bin/env python3
import json, sys

data = json.load(sys.stdin)

for task in data.get("tasks", []):
    name = task.get("name", "?")
    tokens = task.get("tokenCount") or 0
    size = task.get("contextWindowSize")
    # contextWindowSize modeli çözülmemiş görevlerde gelmez
    pct = f" {tokens * 100 // size}%" if size else ""
    status = task.get("status", "")

    print(json.dumps({
        "id": task["id"],
        "content": f"{name} · {status} · {tokens}tok{pct}"
    }))

12 Satır boş kaldığında

Statusline hata mesajı göstermez — sorun çıkınca sadece kaybolur. Sıralı kontrol listesi:

BelirtiBak
Satır hiç görünmüyor Script çalıştırılabilir mi (chmod +x)? Çıktıyı stdout'a mı basıyor, stderr'e mi? Script'i elle çalıştırınca bir şey üretiyor mu? Windows'ta yol ters bölü içeriyorsa düz bölüye çevir. Ayarlarda disableAllHooks: true varsa kaldır. claude --debug oturumdaki ilk çalıştırmanın exit kodunu ve stderr'ini loglar.
Debug'da workspace trust not accepted Bu klasör için workspace trust dialog'u kabul edilmemiş. Claude Code'u yeniden başlat ve güven dialog'unu onayla.
Satır -- veya boş değerler gösteriyor İlk API yanıtı tamamlanmadan alanlar null olabilir. jq'da // 0 gibi yedek değerler koy. Birkaç mesaj sonra hâlâ boşsa Claude Code'u yeniden başlat.
Context yüzdesi beklenmedik En sadesi ve doğrusu used_percentage. /context çıktısıyla farkı, iki değerin farklı anlarda hesaplanmasından gelir.
Bir anda kayboluyor / bayat kalıyor Sıfırdan farklı exit kodu döndüren ya da hiç çıktı üretmeyen script satırı boşaltır. Yavaş script güncellemeyi bloklar; çalışırken yeni tetikleyici gelirse iptal edilir.
Ekranda \e]8;; gibi ham metin echo -e yerine printf '%b' kullan.
Dar terminalde çıktı kırpılıyor Sağ tarafı sistem bildirimleriyle paylaşıyorsun; ayrıca verbose mod token sayacı ekler. Çıktıyı kısalt veya COLUMNS'a göre uyarla.
En hızlı teşhis Claude'a ayar dosyanı okumasını ve statusLine komutunu doğrudan çalıştırmasını söyle — arayüzün yuttuğu hata mesajı böylece görünür hale gelir.
